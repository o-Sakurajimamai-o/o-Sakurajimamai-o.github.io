### 栈与队列 {#cs408-h-02}

* 在对用链表实现的队列或栈中, 插入操作只需要修改尾指针(队尾)或头指针(栈顶), 删除操作需要修改头指针(队头)或栈顶, **但要注意, 对于队列中的删除操作, 若删除后队列为空, 此时还需要修改队尾指针, 设置为 NULL**[^csa-48]
* **前缀表达式**中的逻辑只是把后缀表达式反过来, 即后缀表达式是从左到右进行转化的, 那么前缀表达式就正好相反, 这里举个手算过程的例子, 对于 ${((1 + 2) * 3) - (4 + 2)}$ 来说: 从左向右, 从内向外, 将运算符移动到前面, ${(1+2)}$ 变为 ${(+12)*3}$, 然后处理右侧 ${(4+2) \Rightarrow (+42)}$, 所以 ${((+12)*3)-(+42)\Rightarrow (*+123)-(+42)\Rightarrow -*+123+42}$, 对于计算机程序来说, 做的步骤如下:
  - **反转**中缀表达式。
  - 将所有**左括号 `(` 换成右括号 `)`**，将所有**右括号 `)` 换成左括号 `(`**。
  - 对这个反转后的表达式，使用**中缀转后缀**的算法（使用栈来临时存放运算符）。[^csa-52]
  - 将最终的结果**再次反转**，得到前缀表达式。
  对于前缀和后缀来说, 转中缀的思路是一样的, 利用**栈来保存操作数**, 碰到运算符就依次出栈, 若是**后缀表达式就从左往右**, 若是**前缀表达式就从右往左**模拟

### 树结构 {#cs408-h-03}

#### 树的结构 {#cs408-h-04}

* 设一个树中的最大度数为 ${max_d}$, 则节点总数 ${\displaystyle n=\sum_{i=0}^{max_d}n_i=\sum_{i=1}^{max_d}i\times n_i+1}$ **注意两个下标不一样**

#### 二叉树 {#cs408-h-05}

* 在二叉树的遍历序列中, 对于一个二叉排序树来说, 其中序遍历是一个递增序列, 即中序遍历唯一. 对于二叉树的前序/中序/后序遍历序列数量来说: 若为不带编号的二叉树(即只看树的形态), 这样的个数为 ${\frac{1}{n+1}C_{2n}^{n}}$. 对于带编号的二叉树来说(即使形态一样, 编号不同就认为是不同的树), 这样的个数为 ${C_n\times n!}$. 由前序或后序序列加上中序序列可唯一确定一个二叉树[^csa-59]
* 对于 ${n}$ 个节点的树转二叉树, 树的边数 ${w=n-1}$ 会被分为左指针和右指针, 左指针指向子节点, 右指针指向兄弟, 故有如下性质:
  * **左指针数**：每个**非叶节点**保留一条指向其第一个孩子的左指针，因此左指针条数等于非叶节点数
  * **右指针数**：其余边都用于兄弟关系，即右指针。
  * ${n}$ 个节点的树转二叉树, 对应的不同形态的二叉树为 ${n-1}$ 个结点的二叉树的不同形态, 即用卡特兰计算即可, 原因是因为根节点由于无兄弟(即不是森林), 所以根节点只有左子树, 故计算高度要减一[^csa-63]
* 对于森林转二叉树, 若森林存在 ${n}$ 个非终端节点, 那么对应的二叉树应有 ${n+1}$ 个节点无右儿子. **证明:** 对于 ${x}$ 个根节点, 最右边的根节点一定没有右儿子, 对于 ${n}$ 个非终端节点, 类似与根节点, 每个非终端节点的儿子都会有一个最右儿子没有有兄弟节点, 故总计 ${n+1}$ 个
* 对二叉排序树进行中序遍历会得到升序序列(不是前序遍历)
* 二叉搜索树的查找过程是一个节点一个节点的比较, **并不是看树的高度或路径长度, 而是路径上经过了几个节点**
* 树的路径长度定义为**从根节点到所有节点的总长度之和**, 那么若要求该树的路径长度最小, 每个节点都会尽可能地向上走, 而这恰恰符合了**完全二叉树**的定义, 因此完全二叉树有最小的路径长度;
* 二叉树或 B 树等, 若要寻找一个结点的前驱, 应是它的左子树中的最右节点, **但该节点可能没有左子树**, 此时需要返回到父节点寻找前驱或后继;
* 线索二叉树
  * 二叉链表存储二叉树中, 空指针数为 ${n+1}$, 因为 ${n}$ 个节点应该有 ${2n}$ 个指针, 除去根节点之外的节点均被自己的父节点所指, 所以有 ${2n-(n-1)=n+1}$ 个空指针数, **这些空指针数被用作线索**, 每个空指针指向自己的前驱和后继, 但是一定有两个没有前驱和后继的, 所以此时的**空线索为 ${2}$, 非空线索 ${n+1-2=n-1}$ 个**[^csa-70]
  * 线索二叉树的存储使用的二叉链表, 建立线索二叉树的过程中需要先进行遍历, 遍历过程中若该节点无右孩子则该指针域就指向前驱, 无左孩子则指向后继[^csa-71]
  * 对于前序, 中序, 后序线索二叉树, 寻找其前驱后继是简单的, 根据题目具体描述模拟即可, 但**二叉链表结构不能满足后序线索二叉树寻找其后继**, 存在一种情况, 对于二叉树中该节点的父节点有右子树, 若该节点无右子树, 则其指针域应指向后继, 但后继应该为父节点的右子树的最左节点, 所以**需要三叉链表才能找到这种情况下的后继**, 三叉链表中存储的是: 左右孩子指针域以及父节点指针域[^csa-72]
* 折半查找树
  * 计算折半查找的成功查找长度的时候要把给的序列的长度对应节点转化成折半查找树, 然后每个结点的高度就是查找成功的次数[^csa-74]
  * 折半查找树的形态是趋同的, 即若是一个尽可能向左的二分搜索, 那么就是左子树优先, 否则就是右子树优先, 不可能两种情况同时存在

#### 平衡二叉树(AVL, B树, B+树, 红黑树)[^csa-76] {#cs408-h-06}

##### AVL树 {#cs408-h-07}

* 在平衡二叉树中, 平衡因子是**左子树和右子树的高度差**, 所以能构成平衡二叉树的最小节点数就是每个非叶节点的平衡因子均为 1, 根据高度有如下公式: ${C_n = C_{n-1}+C_{n-2}+1}$, 其中 ${C_0=0,\,C_1=1,\,C_2=2}$; 最多的节点数即为满二叉树; <mark>问: 16个节点的平衡二叉树的最大深度</mark>:由于 ${C_5=12 \lt  16 \lt  C_6=20}$ 故为 5
* 平衡树中删除一个节点再添加, 由于其可以自平衡, 导致可能与原树一样, 但排序树无平衡要求, 故若删除的不是叶节点则一定不同
* 给定任一序列, 确定不同的平衡二叉树数量, 由于需要平衡左右子树大小, 所以要**选择中间尺寸的节点作为根节点**, 然后分别对这些节点进行讨论, 若确定一个根节点后, 其左右子树仍然按照上述方法进行递归确认, 以一个例子说明: `序列{1, 4, 5, 10, 16, 17, 21} 所能确定的平衡二叉树的数量`: 首先由于自平衡要求, 选中根节点集合 `{5, 10, 16}`, 考虑对称, `5` 和 `16` 是对称的, 看 `5`, 左子树确认为 `1, 4`, 有两种可能, 右子树最大高度为 3, 根节点集合为 `16, 17`, 共四种可能, 所以共 ${2\times 4=8}$ 种; 接下来考虑根节点为 `10`, 左右子树 size 均为 3, 由于高度为 2 的平衡树最小节点数为 2, 高度为 3 的平衡树最小节点数为 4, 故左右子树只有一种可能, 所以总的数量为 ${8+8+1=17}$ 种;

##### B树、B+树 {#cs408-h-08}

* B 树的插入与删除操作
  * 插入操作: ${m}$ 阶 B 树最少有 ${(m + 1)/2 - 1}$ 个关键字, 最多有 ${m-1}$ 个关键字, 所以当此时节点的关键字已经满了的时候, 从 ${(m+1)/2}$ (即 ${m/2}$ 向上取整)处分开, **中间的关键字向上一层成为一个关键字的根节点**, 左右两个儿子分别是中间关键字左右的部分, 然后再插入就是插入到子节点中, 若子节点又满了, 还是一样的提出中间关键字向上一层, 若上一层关键字也满了, 那就递归向上[^csa-83]
  * 删除操作: **这里一定注意一点, 删除操作是把当前节点替换为叶节点(终端节点), 即若被删节点不是叶节点, 那么就要找其前驱或后继, 然后进行替换, 替换后删除, 所以本质是删的叶节点**, 具体看王道书, 可分为三种: 直接删除, 左右兄弟够借, 兄弟节点和父节点合并

#### 堆 {#cs408-h-09}

* 关于堆的插入和删除过程中比较次数
  * 在堆的插入中, 是直接插入到最右叶节点, 此时需要调整堆, 方法是: **从该节点开始, 依次与父节点比较, 若大于则交换, 由于原堆性质仍存在, 故不需要其他比较**
  * 在堆的删除中, 首先删除根节点, 然后最右叶节点代替称为根节点, 此时调整堆的方法是: **从根节点开始, 首先比较其两个子节点的值, 选择一个最值, 然后再与其比较, 直到根节点不往下交换为止**
  * 若给定一原始序列要求调整成堆, 需要从最后一个**非叶节点**往前调整

#### 败者树(冠军树) {#cs408-h-10}

* 败者树(冠军树)
  * 败者树适用于多路归并, 所以要先利用外部选择算法选择出初始的归并段, 然后构建败者树, 设初始文件经过内部排序后得到四个初始归并段: `{6,8}; {3,9}; {1, 5}; {2, 7}`, 采用败者树构建过程如下
  * <figure class="fig"><img src="/blog/kaoyan-408/figures/note-20251107194753.png" alt="原笔记配图 2" width="1073" height="599" loading="lazy" decoding="async"><figcaption>原笔记配图 2</figcaption></figure>
  * 败者树的是一颗完全二叉树, 根节点指向最小数, 节点内保存的是归并段号
  * 由图可知 ${k}$ 路-败者树的深度为 ${\lceil log_2k \rceil+1}$, 但败者树的高度为 ${\lceil log_2k \rceil}$(**不计入冠军节点和叶节点**), 与节点数无关
  * 败者树一趟选出一个最小归并段, 比较次数为树高, 但总的比较次数只与初始归并段数有关, 与 ${k}$ 无关, 因此在内存允许的情况下, 增大 ${k}$ 会减少败者树高度, 减少 I/O 次数, 提高外部排序速度[^csa-99]
  * 败者树可以优化生成初始归并段, 即选择-置换排序的效率, 更快的选出 MINMAX
    1. 内存工作区中的记录作为败者树的外部节点，而败者树中根节点的双亲节点指示工作区中关键字最小的记录。
    2. 为了便于选出MINIMAX记录，为每个记录附设一个所在归并段的序号，在进行关键 字的比较时，先比较段号，段号小者为胜者；段号相同的则关键字小的为胜者。
    3. 败者树的建立可从设工作区中所有记录的段号均为 0 开始，然后从 FI 逐个输入w个 记录到工作区时，自上而下调整败者树。由于这些记录的段号为“1”，所以它们对于段号为 0 的记录而言均为败者，从而逐个填充到败者树的各节点中去.

#### (多路)哈夫曼树、编码集 {#cs408-h-11}

* 关于多叉哈夫曼树或者多路归并中需要补空的空节点数量, 考虑这种算法: 考虑 ${n}$ 个节点的 ${k}$ 路最优归并树, 设一个严格 ${k}$ 叉树中有 ${n_0}$ 个叶节点, ${n_k}$ 个度为 ${k}$ 的节点, 那么我们有 ${n=n_0+n_k=k\times n_k + 1}$, 消去 ${n}$ 得到 ${n_0=(k-1)n_k+1\Rightarrow n_k=(n_0-1)/(k-1)}$, 令 ${(n_0-1)\mod(k-1)=x}$, 若 ${x=0}$ 则可以构造 ${k}$ 叉归并, 否则会多出 ${x}$ 个节点, 可以肯定的是 ${x\lt k}$, 于是让这 ${x}$ 个节点构成一个新的归并段, 但这需要额外的一个节点来作为 ${\sum x}$ 的合节点, 故只需要**加 ${k-x-1}$ 个新节点**即可, 有一个节点是在内部, 度为 ${k}$
* 对 ${\displaystyle n}$ 个记录进行多路平衡归并排序, 其归并趟数与选取的归并路数有关, 这里的一个记录是一个归并段, 若给定归并趟数 ${\displaystyle k}$, 那么选取的归并路数应满足 ${\displaystyle k- 1\lt \lceil log_{d}(n) \rceil \leq k}$, 如<mark>对 ${\displaystyle 149}$ 个记录只进行 4 趟多路平衡归并, 那么符合条件的有 ${\displaystyle 4,\,5}$, 而 ${\displaystyle \lceil log_{6}(149) \rceil =3}$</mark>

### 图结构 {#cs408-h-12}

* 无向图中, 每个节点的度是其边数, 所以整个图的度为边数的二倍, 在有向图中, 每个节点的度是其出度和入度之和
* 适用邻接矩阵的情况: 图为稠密图, 频繁查询"任意两点是否存在边", 增加或删除边; 适用邻接表的情况: 图为稀疏图, 频繁遍历邻居或遍历全图; 邻接表使用多很多算法, 如 Dfs, Bfs, Prim, Kruskal, Top Sort;
* 邻接矩阵 A 中, ${A^n[i][j]}$ 表示由顶点 ${i}$ 到顶点 ${j}$ 的长度为 ${n}$ 的**路径条数**[^csa-111]
* Prim 算法时间复杂度为 ${O(n^2)}$, 与边数无关, 适用于**边稠密的图**; Kruskal 算法时间复杂度为 ${O(m\times log_2m)}$, 与点数无关, 适用于**边稀疏, 顶点多的图**

### 查找 {#cs408-h-13}

#### Hash {#cs408-h-14}

* Hash(散列表)的查找不成功平均长度要根据其散列函数来看, 即若数组长度为 10, 散列函数模数为 7, 那么就要计算下标 0~6 的不成功长度, 后面的不算
* 对于 Hash 中查找不成功的计算, 若为拉链法, 则只需搜到有值的指针, 下一个空指针不算做查找次数; 对于探测法, 若当前位置为最后一个有值位置, 且下个位置为空, 则要下一个位置也算做查找次数;
* Hash 映射中拉链法的装填因子计算, 装入 hash 表的节点数要把所有的指针数都算上, 即若对应 2 的链表的 size 为 2, 则这两个都计入装填因子的权值

### 字符串与杂项 {#cs408-h-15}

* 对于两个有序序列合并, 比较次数最差为 O(m + n - 1)
* kmp算法计算的时候, 在我的方法中, 数组的下标是从 1 开始, 所以说 0 位置就是开头(即什么都没有, 把整段向前移), 在遇到 next 数组对应的值为 0 的时候, 此时就整段向前移, 然后 `i+1`, 即 `j=next[j], i++, j++`; **注:** 求 next 数组的时候, 要注意头尾不能在一个子串里, 即 `aaaab`, 对于 b 来说, 它的 next 应该是 4, 即 a|aaa = 3 + 1;
* 在多叉链表中, 其对应的是不同的指针域的链接, 例如二叉链表或者三叉链表, 对应的就是指针域就是三个或者两个[^csa-121]
* 稀疏矩阵
  * 对稀疏矩阵压缩要用到三元组, 一定会失去随机存取的特性
  * 转置用三元组存储的稀疏矩阵 `A[m][n]` 至少需要三个步骤：(1) 将矩阵的行列值相互交换；(2) 将每个三元组中的 i 和 j 相互调换；(3) 重排三元组之间的次序便可实现矩阵的转置, 因为三元组是以行序为主序顺序排列的
* 快排中, 若一趟的定义是对所有的元素都做一遍处理, 那么判断当前序列是否可能为第二趟的结果有如下情况:
  * 若第一趟处理的中枢在首部或尾部(即最大最小值), 那么这一次确定一个最终位置, 接下来的第二趟, 只有一边可以选, 所以还能确定一个最终位置, 此时有两个最终位置
  * 若中枢不在首部或尾部, 那么会确定三个最终位置

### 计算机结构 {#cs408-h-17}

* CPI 是一条指令所需要的时钟周期数, 即反映的是指令在硬件上要跑多少个周期(因为每个时钟周期中的寄存器等等只能用一次), 所以 CPI 与时钟周期无关
* 在计算整个程序段的大小的时候, 题目一般是给出整个代码段, 这个时候根据代码段的第一行, 即起始地址 ${A}$, 以及最后一行, 即终止地址 ${B}$ 来计算, **此时注意**, 最后一行的终止地址并非最后一个指令的起始地址, **而是最后一个指令的起始地址 + 指令字长**, 设最后的字长为 ${x}$ 个编址单位, 则 ${Lenth=B+x-A\,\,或\,\,B+x-1-A+1}$
* 通用寄存器用于存放操作数和各种地址, **由机器字长确定, 字长/机器字长是数据通路的宽度**
* 根据冯·诺依曼计算机结构的原理：
  - 指令和数据都存放在同一存储器中，且格式相同，物理上**没有分开**；
  - CPU 通过程序计数器（PC）指定的地址访问存储器取指令；
  - 通过指令中的地址字段访问数据；
  - 区分指令和数据主要是因为**CPU在不同的指令周期阶段访问存储器**，即取指阶段访问的是指令，执行阶段访问的是数据。
* 字长、机器字长、指令字长、存储字长的区别与联系
  * 字长: CPU 的数据总线一次能同时处理数据的二进制位数，也就是**数据总线(或MDR)的宽度**[^csa-141]
  * 机器字长: 数据通路 (数据总线, MDR) 的宽度
  * 指令字长: **一定要取存储字长的整数倍**，若指令字长的等于存储字长的 2 倍，则需要 2 个访存周期来取出一条指令；若指令字长的等于存储字长，则取指周期 = 机器周期。[^csa-143]
  * 存储字长: 存储器中一个存储单元可以存储的位数，机器字长一般取存储字长的一致或整数倍, 通常与**MDR**位数相等, **指令字长规定为存储字长的整数倍**
  * 主存地址不规定为任何整数倍, 为 MAR(最大寻址空间) 的位数
* CPI 的计算严格依据定义来执行, 即一定的时钟周期内完成的指令数, 即一条指令需要的时钟周期[^csa-146]

### 数据表示与计算 {#cs408-h-18}

* 位数相同的情况下, 移码和补码的表示范围相同
* 计算浮点数的最值范围的时候, 尤其要注意那个几个特殊情况, 如阶码全 1, 阶码全 0 等, 这部分**需要记住**
* PSW 中标志位的作用以及意义
  * CF 为进位/借位标志位, 只对无符号数有意义, 用来判断溢出等问题. 其在加法的时候为进位, 减法为借位, 综合有: ${CF=Sub\oplus C_{out}}$. 所以若两个数相减, ${A-B}$ 时 ${A \gt  B}$ 则 ${CF = 1}$, 若两个数相加时, 没有发生溢出, 那么 ${C_{out}=0}$, 此时与 ${CF}$ 一样, 即加法时: ${CF}$ 与 ${C_{out}}$ 同值; 减法则相反, 若溢出则代表 ${C_{out}=1}$, 根据公式, ${CF=0}$[^csa-151]
  * OF 为溢出标志位, 只对有符号数有意义, ${OF=C_n \oplus C_{n-1}}$, 即若有符号数运算符号位和最高数位进位不同则溢出
  * SF 为符号位, 数字的最高位, 只对有符号数有意义
  * ZF 为零标志, 对两者都有效

* 对于无符号数, SF 和 OF 是无意义的, 可直接排除. 无符号数相减, 被减数大于减数, 则不进位 ZF = 0, CF = 0, 故不溢出应为: ${\overline{ZF+CF}=1}$[^csa-156]
* 对于强制转换的计算顺序, 优先级比乘除要高, 即 `(float)(x+y)/2` 的计算顺序是 `x+y -> (float)(x+y) -> /2`; 对不同类型的变量计算时, 遵循类型升级, 即 `float` 和 `int` 计算, 最后的结果是 `float`, 有符号数和无符号数计算, 结果是无符号数; 对于 `short -> unsigned int` 这类无符号转换, **形式上是进行符号扩展**; 相反的, 对于 `unsigned short -> int` 是进行无符号扩展, **可归结于短字长扩展到长字长时, 根据短字长的类型决定扩展类型**; 对于强制转换类型, 那么只是修改了表示(即有无符号数的定义)[^csa-157]

  ```c
  unsigned int u = 0xffff0fff;
  short s = -3940;
  int i = 50000;
  short temp = u + s;
  int result = temp + i; printf(" %d\n", result);
  ```

  ${\displaystyle result=50155}$
* 海明码的校验与纠错
  * 设海明码有 ${k}$ 位校验位, 数据 ${n}$ 位, 则 ${k}$ 需要满足 ${2^k \geq n+k+1}$, 然后发送发需要把数据转化成海明码的格式, 这里以 `1001011` 举例, 需要 ${k=4}$ 位校验位, 发送的数据共 11 位
  * 设置海明码位置, 习惯性的设在 ${2^i}$ 位, 即 ${1, \,2,\,4,\,8}$; 接着计算这四个位置应该存放的数字 ${a_i}$ 应该满足除去海明码位的所有位置 ${j}$ 对应的二进制位在 ${i}$ 位为 1 的位置的异或和, 例如计算 ${a_1}$, 那么在 ${3,5,6,7,9,10,11}$ 中对应的二进制第一位(${2^0}$位)为 1 的数字分别是 ${3, 5,7,9,11}$, 故 ${a_1=a_3 \oplus a_5 \oplus a_7\oplus a_9\oplus a_{11}=1}$, 同理 ${a_2=a_3\oplus a_6\oplus a_7\oplus a_{10}=0}$, 依次得到 ${a_4=1}$, ${a_8=0}$, 故发送的数据为 `10110010011`[^csa-167]
  * 接收方进行纠错, 纠错的方法与设置海明码方法类似, 求出四个海明码对应位置的值 ${h_i}$, ${h_i}$ 的计算方法和设置海明码方法一样, 不过后面还要再异或一个 ${a_i}$, 例如接收方收到 `10110110011`, 那么 ${h_1=a_3 \oplus a_5 \oplus a_7\oplus a_9\oplus a_{11}\oplus a_1=0}$, ${h_2=a_3\oplus a_6\oplus a_7\oplus a_{10}\oplus a_2=1}$, 同理 ${h_4=1,\,h_8=0}$, 故得到 0110, 表面第六位出错, 把第六位取反即可, 若得到 0000 则证明无错[^csa-168]
* 机器零的概念: **只存在于浮点数, 表示下溢**, 并不是真的零, 它代表该数小于最小可表示的数, 只要尾数为 0, 无论阶码大小都被认为是机器零; 因此, **只有以移码表示阶码**的时候, 才能用全 0 表示机器零, 因为移码是将负值区间挪到正值区间了, 所以移码全零对应着最小的负数[^csa-169]
* IEEE 754 浮点数的数值范围
  * 规格化数(阶码不全为 0 也不全为 1): 最小规格化数为 ${1.0\times 2^{1-bias}}$, 最大规格数为 ${(2-2^{-p})\times 2^{(2^{k-1}-2)}}$, 其中 ${p}$ 为尾数有效位, ${k}$ 为阶码位数[^csa-171]
  * 非规格化数(阶码全为 0，但尾数不为 0): 最小正非规格化数为 ${1.0\times 2^{1-bias+p}}$ (对应尾数为 0.00..01, ${p}$ 为尾数有效位(23或55))[^csa-172]
* 在**浮点数的舍入**中, 其余三种方法较为简单, 重要的是就近舍入, 即保留一定的位数作为浮点数的舍入, 这些保留的位数采用就近舍入, 即最接近最低位的是否为 1, 若为 1 则采用 +1 舍入, 否则截断[^csa-173]
* 两个规格化浮点数运算, 得到的数可能是非规格数, 如: ${\displaystyle A=0x00800001,\,B=0x80800000}$, 则 ${\displaystyle A+B=0x00000001}$
* 加法器, 乘法器, 除法器
  * **无论有无符号数相减**, 对于 `x-y` , 加法器两端应原封不动的送 x, 对 y 按位取反, 然后 sub 取 1
  * ALU 中是否进行部分积与被乘数的加法运算由乘数的最低位决定(0不动, 1相加)
  * 原码乘法移位时, 应将进位位, 部分积, 乘积部分一起进行**逻辑右移**
  * 快速列阵乘法器**不包含**移位器
  * ${\displaystyle n}$ 位**乘除法**大约需要 ${\displaystyle n}$ 次加减运算和 ${\displaystyle n}$ 次移位运算, 应注意符号位的一次异或

### 存储系统 {#cs408-h-19}

#### 存储器分类与功能 {#cs408-h-20}

* 各种存储器的分类与作用
  * 随机存取存储器(RAM, 有易失性); 只读存取存储器(ROM, 也具备随机存取, 写速比读速慢); 顺序存取存储器(磁带, 只能顺序存取); 直接存取存储器(磁盘, 光盘, 在存取的过程中, 既有随机存取(找磁道), 又有顺序存取(找扇区));
  * 静态存储器(SRAM, 功耗大, 非破坏性读出, 无需刷新); 动态存储器(DRAM, 功耗小, 破坏性读出, 读后需再生(仅针对读出的单元), 且需要定时对数据刷新(单位位行)以防数据消失);
* 主存由 RAM 和 ROM 实现, 控制存储器(微程序里的)由 ROM 实现
* **地址存储器 MAR 的位数取决于计算机中寻址空间的大小**, 即又要看计算机的主存地址空间大小, 还要看计算机的编址方式, 如 16位计算机有 128KB 的地址空间, 那么其 MAR 位数就是 128KB/2B = ${2^{16}}$B, 即 16 位[^csa-188]
* 按边界存储的对齐规则为: 存放至该类型大小的整数倍字节处, 若为 ${short}$ 类型, 即需要存放到 2 的整数倍, 同理 ${int}$ 为 4 的整数倍, 因此若此时要存放的地方要是不满足, 要空出对应的字节数; **注意:** C语言对变量类型默认采用边界对齐方式, 浮点数默认 IEEE754 格式[^csa-189]
* 主存地址是主存块号 + 块内偏移位, 主存块号就映射到 Cache 的 ${tag}$ + cache 组号字段, 偏移位一样
* 储存周期是指: **从开始一次访问到该存储体可以开始下一次独立访问所需要等待的最短时间**, 这里面不包含数据传输的时间[^csa-191]
* 关于 DRAM 的刷新
  * DRAM 每次刷新会把自己的要刷新的那一行读入 DRAM 内置的行缓冲寄存器(用 SRAM 实现), 故其大小应为一行的比特数
  * DRAM 的刷新不依赖外部的刷新, 对 CPU 是透明的(再生不一样)[^csa-194]
  * DRAM 刷新只需要行地址, 不需要片选信号指定
  * **多个 DRAM 与一个 DRAM 刷新次数是一样的**, 因为每个 DRAM 刷新次数都是独立的, 所以他们并行刷新, 花费的时间为一个 DRAM 刷新的次数, 即一个 DRAM 的行数
  * 下面给出一个综合性的题目: <mark>现在有 16 个 1M X 4 位的 DRAM 芯片，其中每 2 个芯片位扩展构成一个 1M X 8 位的 存储体，对这些存储体进行低位交叉编址构成一个 8MB 存储器。存储器按字节编址，且与 64 位的存储器总线相连，主存每次最多能读写 64 位数据，存储周期为 1ns。</mark>:
    1. 每个 DRAM 芯片是 1M x 4 位，DRAM 芯片有 1024 行 1024 列, 给定一个行号会把该 行对应的所有数据都读出到芯片的行缓冲寄存器里，行缓冲寄存器的单元个数与列数相同, 宽度为 4 位，所以一个芯片的行缓冲寄存器大小为 ${\displaystyle 1024 \times 4bit}$，存储器的行缓冲总大小为 ${\displaystyle 1024*4*16/8=8192B}$ ;行缓冲寄存器一般采用 SRAM 实现。
    2. 存储器是按字节编址的, 也就是对于存储器而言一个字节对应一个存储单元。一块芯片可以提供 4 位数据，那么选中存储器一个单元时就会选择一个存储体的一个单元，选择一个存储体的单元同时选中了相同地址的两块 DRAM 芯片的 4bit 的单元，同时输出到存储器总线的 8 根数据线上。位扩展不会影响存储单元个数，会增大存储单元大小，地址数量不变，一个地址对应 的数据宽度增加。字扩展不会影响存储单元大小，会增大存储单元个数，地址编号个数增加，一个地址 对应的数据不变。
    3. DRAM 芯片会使用地址引脚复用技术，地址引脚位数是 10，数据引脚位数是 4，${\displaystyle 10 +4 = 14}$ 位
    4. double 型变量 x 的主存地址为 `01 2345H`, 总线是 64 位，同时启动方式下，一个存储周期启动 8 个体， 各提供 1B 数据，由于采用低位交叉编址，则主存地址构成为：20bit 块内地址 + 3bit 块号， 所以这 8B 数据的地址前 20 位相同，后三位地址从 000 到 111，分别代表 8 个存储体。x 的地址低三位是 101，第一个存储周期同时启动后得到 `01 2340H` 到 `01 2347H` 的 8B 数据，其中 `01 2345H` 到 `01 2347H` 是 x 的前三个字节，第二个存储周期会得到从 `01 2348H` 到 `01 234FH` 这 8B 数据，01 2348H 到 01 234CH 是 x 的后五个字节，所以读取 x 需要两个存储周期。
    5. 刷新是芯片内部的硬件来完成的，刷新时整个存储器的所有芯片的同一行同时进行刷新，只需要考虑一个芯片的刷新情况。一次刷新需要一个存储周期(1ns)，集中跟异步刷新方式下刷新所有行需要的时间都为 1024ns。刷新时间内 CPU 不允许访存，即死区时间为 1024ns(区别在于死区时间是否连续)；每个刷新周期内需要对所有行都刷新一遍，所以死区时间占比为 ${\displaystyle (1024/20480)*100 =5}$[^csa-202]
* SRAM 和 DRAM 芯片的排线数和数量计算
  * 形式如 `8MB x 8` 位, 这里的 8MB 为地址空间, 即地址线位数为: ${log_{2}(8MB=2^{23})=23}$ 位, 8 位是数据线个数, 故总共需要 ${23+8=31}$ 个引脚数, 若为 DRAM, 地址线行与列对半分, 分两次传送, 故只需要 ${11.5}$, 即 11 行, 12 列(考虑最优分配, 行数要小), 故总共需要 ${12+8=20}$ 引脚数;[^csa-204]
  * 若要求需要的 Ram 芯片, 则**首先观察计算机按什么单位编址**, 然后计算需要使用的总地址空间大小以及单个 RAM 芯片的大小, 然后相除向上取整即可
  * 若芯片进行双扩展, 这里给出例子: <mark>"若干 8K x 8位的芯片组成一个 32K x 32 位的存储器, 存储字长为 32 位, 内存按字编址, 求地址 41F0H 所在芯片的最大地址"</mark>; 首先进行位扩展, 4 个芯片组成一个 8K x 32位的芯片, 直接接到数据线即可, 无需片选; 然后进行字扩展, 明显的需要 4 组位扩展后的芯片, 所以高 2 位进行片选, 每组芯片可表示 ${8K=2^{13}}$, 即 13 位的地址空间, 所以**第 ${1 \sim 13}$ 位表示地址空间, ${14 \sim 15}$ 进行片选**, 故 ${41F0H=010|0...}$, 对应最大地址为 ${010|1FFFH =5FFFH}$
* 一次总线事务过程包括:
  * 送首地址和命令
  * 存储器准备/读取数据, 准备数据阶段的时间花费的是一个存储周期的时间
  * 将数据放到数据总线传送数据
  * **注:对于多模块交叉存储器来说, 送完地址之后, 第一个体需要花费一整个存储周期的时间, 然后紧接着的所有体都按照流水线的方式进行准备**, 即 ${n}$ 位多模块交叉存储器所需要的时间是(假设传输地址和命令需要 1 个时钟周期, ${T_{总}}$ 是总线时钟周期): 送首地址和命令(1个时钟周期) + 存储时间(第一个体准备数据的时间) + ${n\times T_{总}}$ (传输一位数据需要一个总线周期)[^csa-211]

* 多模块存储器的低位交叉编址分为两种启动方式, 一种是轮流启动方式, 另一种是同时启动
  * 多体并行存储器拥有多个模块, 每个模块拥有自己的存储体, MAR, MDR, 读写/控制电路, 每个模块都是一个独立的存储器
  * **当每个模块传输的位数等于数据总线位数**, 就采用轮流启动, 其具体存储过程在前面的一次总线事务提到过, 设其存取周期位 ${T}$, 总线周期为 ${r}$, 则模块数应大于等于 ${m=T/r}$, 每隔 ${1/m}$ 个存取周期就会有读写一个数据, 在此过程中可能会发生冲突
  * 当**所有的模块位数之和等于数据总线位数**, 此时为同时启动, 即一块送到总线, 正好是总线位数的大小, 在此过程中, 可能传输没用的位数. 比如计算器由 4 块 ${64KB \times 4}$ 位的 DRAM 交叉编址构成, 主存每次最多读写 32 位数据, 取一个 double 类型的数据(8B), 其主存地址为 ....AH, 由于模块数为 4, 那么主存地址最低两位为 10, 且数据总线 32 位, 故模块总位数等于数据总线位数, 采用同时启动, 存取流程为: 00, 10, **10, 11; 00, 01, 10, 11; 00, 01**, 10, 11; 由此可发现未标红的为无用位数[^csa-216]
  * 对于多体交叉存储器来说, 访问的过程中可能会产生体冲突, 例如对 4 体交叉存储器, CPU 访问的主存地址序列为 `03，09，11，02，33，25，0D，04，08，29，43，0A` (均为16进制), 理想情况下，每隔 1/4 周期可读写一个数据，假定这个时间为 𝛥𝑡。每个存储模块内的地址分布为地址二进制的后两位, 即模块 0：00、04、08、0C、10; 模块 1：01、05、09、0D、11、25、29; 模块 2: 02、06、0A、0E、12; 模块 3: 03、07、0B、0F、13、33; 很显然，如果相邻 4 次访问中给定的访存地址出现在同一个模块内，就会发生访存冲突。所以 11 和 09、25 和 11、0D 和 25、08 和 04... 会发生冲突。29 和 0D 也在同一个模块内且访问间隔小于 4 个 𝛥𝑡，但是，由于访问第 08 单元发生冲突而使其访问延迟 3 个 𝛥𝑡 进行，从而使得 29 号单元 也延迟 3 个 𝛥𝑡 访问，因而，其访问不会和 0D 号单元的访问发生冲突.
  * 由于多模块存储器是按照流水线启动的, 所以当稳定下来之后, 其平均传输速度应按照流水线情况, 即一个周期传送一个体

#### Cache {#cs408-h-21}

* 对于一个指令, 一定要仔细观察到底访问几次, 如: a[x] = a[x] + 1; **这里的 a[x] 实际上是被访问了两次**
* 直写方式若无特殊说明, 就算是写入队列缓冲也算作一次访存
* 关于 Cache 效率的计算, 首先计算 Cache 命中率 H, 然后求平均访问时间 ${T_A=H\times T_C +(1-H)\times T_M}$, 主存慢于 Cache 的倍率为 ${r=\dfrac{T_M}{T_C}}$, 此时 Cache 的效率为: ${e=\dfrac{T_C}{T_A}=\dfrac{1}{H+r(1-H)}}$, 存储器性能提升倍数 ${X = \dfrac{T_M}{T_A}}$[^csa-222]
* 主存和 Cache **各自有独立的地址空间**, Cache 地址映射到主存地址空间, 其中对于不同的 Cache 映射方式有不同的 Cache 地址结构:
  * 直接映射的 Cache 地址结构: 行号 + 块内地址
  * 全相联映射的 Cache 地址结构: 行号 + 块内地址
  * 组相联映射的 Cache 地址结构: 组号 + 行号 + 块内地址
  * **注:** 虽然 Cache 地址包括组号与行号, 但是 Cache 结构是不包括组号与行号的, 其中包括有效位, Tag, 数据(行长), LRU(若有), 脏位(若有).
  * **注:** Cache 的容量是指 Cache 的存储容量, **不包括标记阵列（标记位、有效位、脏位等）**, 但 Cache 总位数或 Cache 总容量计算时包括标记阵列
  * **注:** Cache 的控制字段即为标记阵列, 即有效位, Tag, 脏位, LRU位等等
  * ${d}$ 路组相联中, 当根据主存地址确定了具体的组号之后, 需要用 d 个比较器(相联存储器)选中 1 行, 然后用一个多路选择器**选中一个块**, 多路选择器具体使用的位数要看一行 Cache 能存储多少个主存块[^csa-230]

#### 磁盘 {#cs408-h-22}

* 在计算磁盘平均读写时间时, **一定要记住刚开始滑到目标扇区下边的平均时间是转半圈的时间**(若题目特别说明磁头一开始的位置, 则不用这个计算); 磁盘的数据存取速率可能不会显式的给出, 但是根据磁盘一圈的数据量和转一圈所需要的时间便可得出数据传输速率
* 道密度是半径方向单位长度包含的磁道数, 位密度是磁道单位长度存储的数据量, **随着半径增大, 道密度不变, 位密度减少**
* RAID 独立冗余磁盘阵列
  * RAID0: 无冗余和无校验的磁盘列阵, 利用**条带化技术, 使得读写速度在 RAID 中最快**
  * RAID1: 采用镜像磁盘阵列, 两个磁盘当一个磁盘用, 提高了安全可靠性
  * RAID2: 采用海明码纠错, 提高了安全可靠性
  * RAID3~5: 均采用奇偶校验, 提高了安全可靠性

### 指令系统与 CPU {#cs408-h-23}

#### 指令系统 {#cs408-h-24}

##### 指令格式 {#cs408-h-25}

* PC + "1" 的 "1" 是计算机的编址方式大小, 如: 16位计算机中一个指令两个字节, 由于 2B = 16bit, 此时一条指令导致 PC = PC + 1[^csa-242]
* 一般的中断、I/O 相关指令、设置/修改内存管理寄存器或 PSW 指令均为**特权指令**, 算术逻辑、数据传送指令(内存传送, 寄存器之间传送等)、控制转移指令((无)条件转移、返回/调用等)为非特权指令[^csa-243]
* 指令格式, 计算机对应的编码
  * 设计算机为 16 位计算机, 则对于定长操作码编码有: 半字长指令(8位, 常见于 RR 型指令),  单字长指令(即指令长度为 16 位, 具体格式由题目给出), 双字长指令(32位, 一般第二个字是偏移量或有效地址)
  * 对于指令格式, 有如下几种常见类型: **RR 型**(寄存器-寄存器型), **RX、RS 型**(寄存器-存储器型指令, 其中 RX 型格式为 `OP R1 X B D`, 其中 X 为变址器, B 为基址器, D 为偏移量, 即**一个寄存器操作数 R1, 一个存储器操作数** `EA = D+(X)+(B)`; 而 RS 型格式为 `OP R2 R3 B D`, 即**两个寄存器和一个存储器**, `EA = (B) + D`), SI 型(存储器-立即数型), SS型(存储器-存储器型)
  * 有了以上的分析, 若题目给出一个指令为: ${(F0F1)_H(3CD2)_H}$ 和 ${(2856)_H}$, 可以看出, 第一个指令为双字长指令, 第二个指令为单字长指令, 因此可以根据题目给出的指令格式去判断其代表的操作
  * 定长指令字的操作码部分只由 `OP` 段决定, 即 `OP` 的位数代表了所有的操作数, 而变长指令字可以通过操作码扩展, 从而增加操作数个数, 例如 20 位的指令, 地址字段占 8 位, 有两个地址段, 所以 `OP` 占 4 位, 若采用定长指令字, 则二地址操作数最多有 ${2^4-2=14}$ 种(留两个保留给一地址、零地址指令); 若采用变长, 则只需留一种情况给零、一地址操作码即可, 即最多有 ${2^4-1=15}$ 种;[^csa-248]
  * 定长指令字由于长度一定, 所以**不需要 PC 计数器**, 而变长指令字需要; 变长指令字可以按照最长的指令长度进行读取, 然后再进行具体的划分操作, 从处理器设计的角度来看, 定长指令字格式更好[^csa-249]
  * 有两种指令可能有隐藏的操作数, 一是零地址指令, 它的操作数来自于**栈顶和次栈顶**, 二是一地址指令, 它的操作数来自于 **ACC**
* MIPS 汇编语言和机器语言
  * MIPS 是典型的 RISC 处理器, 按字节编址, 采用 32 位定长指令字, 操作码也是固定长度, 若给出的位数为 16 位, 则需进行符号或 0 扩展
  * 有三种指令格式, 分别为 R-型, I-型, J-型; 其中**J-型指令**形式为`OP(31-26) 直接地址(25-0)`, 主要是无条件转移指令, 其计算方式为: **当前 PC 的高四位拼上直接地址 26 位, 最后右移两位(添两个0)** 就可以得到转移目标地址, 添两个 0 的原因是一个指令必须占 4 个存储单元(32位), 因此最后两位总是 0, 无需在指令中给出[^csa-253]

##### 指令周期与寻址方式 {#cs408-h-26}

* 一条指令对应一个微程序, 即两者均用一个指令周期
* 在偏移寻址的过程中, 一定不要忘记其计算方式为(从当前偏移指令地址开始): **PC = PC + "1" + Offset ${\times}$ "1"**; (**补充:** 说法并不正确, 还是要看具体的偏移寻址方式, 若为相对寻址, 那么就直接 + "1" + Offset 即可, 上述大多数是用变址寻址便于数组循环, 所以不用死记硬背, 理解即可)[^csa-256]
* 指令的执行周期结束后, 会检查是否有中断请求, 若有, 则进入中断周期, 中断周期中 CPU 做一些准备工作（保存断点、关中断、取中断向量等），然后跳转到中断服务程序的入口地址。之后, 中断服务程序(ISR)是一个具体的程序(代码, 但不是进程), 具有多条指令
* 在指令执行过程中, 取操作数等寻址方式, 类似于 `R[R1]` 这种为寄存器寻址, 而 `M[imm]` 属于直接寻址, 即操作数即为内存地址[^csa-258]
* MIPS 过程调用, 假定过程 P 调用过程 Q, 则过程调用的执行步骤如下
  1. P 将入口参数放到 Q 能访问到的地方
  2. **P 将返回地址存到特定的地方**, 然后将控制转移到Q
  3. **Q 为 P 保存现场**，并为自己的局部变量分配空间[^csa-262]
  4. 执行过程 Q
  5. Q 将返回结果放到 P 能访问到的地方
  6. Q 取出返回地址, 将控制转移到 P

#### Cpu与数据通路、控制逻辑 {#cs408-h-27}

* 寄存器读口 rs 使用的是**多路选择器**, 这样做的原因是快速, 纯组合逻辑, 并且支持多端口读入; 而寄存器写口 rd 使用的是**地址译码器**, 因为 rd 需要指令指出, **需要严格的时序控制, 地址译码器确保唯一性, 避免误写**
* 单(多)周期处理器
  * 指任何一条指令在一个时钟周期完成, 因此每条指令的 CPI 为 1, 计算机的时钟周期要按照所有指令中最大处理时间设置.
  * 注意单处理周期处理器并不指单总线, 单总线上一个时钟周期只能传送一个信号, 因此不适用单周期处理器
  * 单周期处理器中, 每个时钟周期内计算机部件只能被使用一次
  * 单周期数据通路中, 由于一条指令在一个时钟周期完成, 故 PC 在该时钟周期一定会被写入, **不需要写使能**; 由于多周期数据通路要和流水线结合, 在各个流水段中, 有的流水段 PC 不需要被写入, 有的流水段需要写入 PC, 所以**多周期需要写使能来控制 PC 何时写入**[^csa-272]
  * 在上述的单周期处理器中, 不仅仅 PC 不需要写使能, 在指令执行过程中没有任何状态元件被写入信息，否则一个指令周期不可能在一个时钟周期内完成, 所以无需指令寄存器(IR)[^csa-273]
  * 在该时钟周期内, 一条指令只需要一个时钟周期, 控制信号一次性生成且不再改变; 而多周期控制器则需要各个流水段调和来完成一条指令, 所以在指令执行过程中需要改变控制信号的值
* 关于操作序列中 MAR 和 MDR 对存储器进行读写操作, 其占用的线分别为**地址线和数据线**, 并不占用内部总线, 故可以与其他操作序列放在一个时钟内并行执行

##### Cpu流水线 {#cs408-h-28}

* 关于普通的数据相关判断(即不是 load-use)只需要看两个相关寄存器使用修改之间是否超过两条指令即可, 因为存回到取数需要间隔 2 个流水段[^csa-277]
* MIPS 的流水段(IF, ID, EX, MEM, WB)中, IF, MEM 阶段均可能访存从而引起缺页中断异常, EX 阶段要进行**溢出判断**, 可能引起溢出异常, 外部中断则需要在指令完成后, 即 WB 阶段后, 而 ID 阶段会进行译码等, 可能引起**无效指令操作码**等异常
* Cpu 流水线中, 取指令和译码阶段动作是一致的, 不需要控制信号控制; **控制信号在译码阶段统一产生**, 同样和数据一起跟随流水线寄存器进行传递, 传递到具体的相关流水段就把对应的控制信号输入对应接口
* 流水线技术
  * 流水线性能指标: 吞吐率 = ${TP=\dfrac{n}{T_k}}$, 即单位时间完成的任务; 加速比为不用流水线的时间 ${T_s}$ 与使用流水线的时间 ${T_k}$ 比值 ${S=\dfrac{T_s}{T_k}}$; 效率是流水线中的**设备实际使用时间与整个运行时间的比值**，即流水线利用率, 对于流水段长相等的流水线, ${e=\dfrac{n\Delta t}{T_k}}$, 也可用定义计算: ${e=\dfrac{时空图中任务所占面积}{时空图总面积}}$
  * 对于流水段长都相等的流水线, 此时的时空图和 Cpu 流水线的时空图无异, 此时完成所有任务需要的总时间为 ${T_k=k\Delta t + (n-1)\Delta t}$
  * 对于流水段不相同的流水线, 其时间最长的流水段称为流水段的瓶颈段, **需要重复设置瓶颈段**, 使其每隔一个时钟周期进行一个瓶颈

* 关于 Cpu 流水线方式, 这里总结一下
  * 对于一般 RISC 指令集的 Cpu 流水来说, 分为五段, 分别为: IF, ID, EX, MEM, WB; 中间涉及的冲突有: 结构冒险(硬件冲突), 数据冒险, load-use, 控制冒险;
  * 对于数据冒险来说, 若不采用半周期读写寄存器, 不采用数据旁路, 则需要等到上一条指令 WB 结束后, ID 才可以执行, **此时需要阻塞三个时钟(EX, MEM, WB)**; 若只采用半周期读写寄存器, 则在 WB 的后半周期就可以执行 ID, **此时需要阻塞两个时钟(EX, MEM)**; 若采用数据旁路技术, 则在 EX 完之后就可以直接转给下一条指令, 可以解决冲突, **无需阻塞**
  * 对于 load-use, 若不采用半周期读写寄存器, 不采用数据旁路, 则需要等到 WB 结束后, **此时需要阻塞三个时钟(EX, MEM, WB)**; 若只采用半周期读写, **同上需要两个时钟**; 若采用半读半写和数据旁路, 则只需要 MEM 阶段之后, 数据旁路直接转发到 ID-EX 流水段寄存器, 故**只需阻塞一个时钟(MEM)**;
  * 对于控制冒险, 由于各种跳转指令在不同的阶段 PC 的值改变, 如 `beq` 指令或 `J` 型指令均在执行阶段生成转移地址, 于是在 MEM 阶段就可以通过写控制信号, PC 经过多路选择器来获取下地址, 所以基准基本上是在 PC 确定之后的下一个操作取指令(IF), 若无特别说明, 跳转指令一般会在 **MEM 阶段之后确定最终 PC 的值**, 则下条指令需要阻塞 3 个时钟(ID, EX, MEM). **注意:** 可能存在 load-use 冲突, 那么就要加一个时钟, 因为跳转指令需要加一个时钟, 其对应的下一个指令自然需要阻塞 3+1 = 4 个时钟
  * 关于数据冒险判断: 记住要根据流水线是否冲突以及**当前指令是否用到了特定指令的寄存器值**, 若 t1 修改了 R1 的值, t2 也修改了, t3 要用, 那么就是 t3 与 t2 的数据冒险, 与 t1 无关, **判断数据冒险时, 忽略掉寄存器半读半写以及分支转发, 只从流水线分析冲突**
  * 关于分支冒险判断: 只需要判断当前指令是否可能产生分支冒险即可, 常见于(有/无)条件跳转指令

### 总线与设备 I/O {#cs408-h-29}

#### 总线系统 {#cs408-h-30}

* 在异步总线中, 两个设备由于速度差异过大, 完全依靠双方互相制约的握手信号, 故需要按需分配时间
* I/O 总线中: 数据缓冲寄存器和命令/状态寄存器的内容均通过数据线传输; 地址线用以传送与 Cpu 交换数据的端口地址; 控制线用于给 I/O 端口发送读写信号, 仅用于对端口的读写控制
* 异步串行通信方式在传输字符时由于双方时钟不严格一致, 因此每传输一次字符(**一次可能传输多位数据**)都要用**起始位和停止位作为开始和结束的标志**
* 总线带宽的**最大传输速率**是指所有时钟周期都在传输数据, 而**平均传输速率**是考虑实际情况下(即传指令地址, 准备数据等时间)的传输速率, 故最大传输速率本质上就等于: 时钟周期数 ${\times}$ 每时钟周期传送的数据量[^csa-296]

#### I/O 系统 {#cs408-h-31}

##### 中断 {#cs408-h-32}

* 中断处理和子程序调用都需要压栈以保护现场, 两者都会保存PC, 中断处理保存 PC 用来断点处的程序继续进行, 子程序调用保存 PC 便于运行完子程序回到主程序继续进行; 而由于中断随时可能改变, 防止上一个程序的中断处理程序再次被其他中断打断, 所以中断处理必须保存 PSW; PSW 通常不会被调用指令自动修改且函数在同一处理器模式下运行（通常不改变中断使能、特权级）, 所以没有必要保存整个 PSW。[^csa-302]
* 中断响应过程是执行中断隐指令的过程, 而中断响应周期则是执行完中断隐指令之后进行的周期, 即中断响应过程是在指令周期中的中断周期做的, 而中断服务程序则是在中断响应周期[^csa-303]
* 中断判断优先级有软件和硬件两种方式, **中断向量属于硬件判优的结果**[^csa-304]

##### I/O 传输方式与计算 {#cs408-h-33}

* 若一个设备的要求的传输速率为 ${x\,B/s}$ 且对应接口的数据缓冲寄存器大小为 ${y\,B}$, 那么 Cpu 最多相隔 ${\dfrac{x}{y}\,s}$ 查询一次, 不然会造成数据覆盖, 数据损失[^csa-306]
* DMA 在 I/O 过程中完全是由硬件控制的, 而在传输数据结束后, 会向 Cpu 发送结束中断信号, 此时 Cpu 会执行中断服务程序, 这一步是 DMA 控制器告知 Cpu 数据传输已完成, 可以进行下一步工作, 并且在中断服务的过程中, Cpu 会查看 DMA 控制器的程序状态字看看是否数据有错误, 即**DMA控制器进行数据检验错误, 并记录到自己的状态字寄存器中, 然后传输结束后一并告知 Cpu, Cpu 来处理**.
* DMA 控制器中有字计数器, 表示该次 DMA 传输的块数, 此时注意: 若计数器为 ${n}$ 位, 每传输一个数据块计数器减一, 若当计数器为 0 时表示传输完成, 则总共传输 ${2^n-1}$ 个数据块; 若当计数器溢出时表示传输完成, 则总共传输 ${2^n}$ 个数据块[^csa-308]
* **外部设备发出 DMA 请求**, DMA 控制器收到后, 向 CPU 请求总线, CPU 响应使其获得总线控制权

### 操作系统功能与进程 {#cs408-h-35}

#### 操作系统分类与功能 {#cs408-h-36}

* 操作系统中的引导过程和磁盘初始化
  * 磁盘安装操作系统:
    * 将磁盘低级初始化(低级格式化), 即分成扇区, 由头部数据区和尾部组成, 利用磁道号, 磁头号, 扇区号来标志一个扇区
    * 将磁盘分区(C, D盘), 每个分区的起始扇区记录在磁盘主引导记录的分区表(PBR)中[^csb-319]
    * 对磁盘逻辑格式化(高级格式化), 将初始文件系统数据结构(即**文件的全局信息**等)存储到磁盘上, 建立根目录, 对空闲磁盘块信息初始化
  * 操作系统引导:
    * 激活 Cpu 读取 Rom 中的 boot 程序(**Rom引导程序**), 执行 BIOS 指令
    * 硬件自检, 在内存最开始的部分构建中断向量表, 然后利用中断检查是否有故障
    * BIOS 读取启动程序, 加载带有操作系统的硬盘, 启动**磁盘引导程序**, Cpu **将该引导扇区加载到内存中**
    * 加载主引导记录(MBR), 通过 MBR 去找启动设备, 然后 MBR 扫描硬盘分区表, 找到并加载硬盘活动分区(**分区引导程序**)[^csb-325]
    * 活动分区的第一个扇区, 称为分区引导记录(PBR), 其作用是寻找并激活分区根目录下的引导操作系统的程序(即启动操作系统管理器)
    * 找到之后加载管理器并启动操作系统, 随后将**操作系统加载到内存**
    * 需要注意的点: ROM 中存放的是操作系统引导程序, ROM 负责初始化硬件, 启动引导加载程序等; 而所有运行中的程序数据、文件缓存等都会存放在 RAM 中.
* 多道程序系统的四个特征: 并发, 共享, 虚拟, 异步; 其中**并发和共享**是基本特征, 而单道程序系&gt;统具有封闭性, 多道程序没有封闭性
* C程序经过预处理 ${\to}$ 编译(将高级语言转化为低级语言(汇编语言)) ${\to}$ 汇编(进一步的将汇编语言转化为机器语言) ${\to}$ 链接 ${\to}$ 装载
  * 在这个过程中, 链接是**形成逻辑地址的模块**, 其作用是将不同的文件合并, 然后分配一个连续的逻辑地址, 而完成该变换的过程阶段是**装载(设置页表，使逻辑地址 ↔ 物理内存建立映射)**
  * 装载(装入)阶段有三种不同的装入方式; 对于**绝对装入**方式, 只适用于单道程序作业, 此时已经知道作业在内存中的具体物理位置, 因此逻辑地址与实际物理地址相同; **静态可重定位装入**方式中的指令和数据地址也从 0 开始, 但是是相对于始值, 因此可以选择装入到内存中的选定始值部分, 一次完成; 以上两种方式均是一次装入, 占用的连续内存空间为作业的大小; **动态可重定位装入**方式与上述不同, 其相对地址在装载的过程中不会转换, 等到真正要用的时候再去进行地址转换, 因此其地址空间并不连续且是**在程序执行阶段才进行地址转换**, 在重定位过程中需要一个 **重定位寄存器(基址寄存器)** 来进行地址转换并用界地址寄存器进行越界检查, 物理地址为重定位寄存器 + 相对地址;[^csb-332]
* 系统调用过程, 用户进程进入内核态, 这个过程中, 用户栈的部分内容(寄存器, 栈指针等)会存入内核栈以供内核代码使用, 而 PCB 只保存内核栈的上下文(如系统调用参数, 返回地址, 内核栈指针等); 在系统调用或中断服务程序执行期间, 除了中断响应过程是原子过程, 后半段是可以被调度阻塞的(考虑多重中断等操作)[^csb-333]
* 各类数据的存放区
  * 代码段或函数: 存放可执行代码
  * 只读数据段: 存放常量(局部**常量**, 全局**常量**)[^csb-336]
  * 读写数据段(初始化后的数据段): 存放可读写的全局变量与静态变量[^csb-337]
  * 堆: 存放动态分配(malloc/new)的内存
  * 栈: 函数参数, 局部**变量**(函数指针), 返回地址等**每线程独立的栈帧**
* 线程中对于各类数据的共享与独享分析
  * 对于代码段, 只读数据段, 读写数据段, 堆中的数据, 文件描述符等属于进程内部数据, 堆属于进程地址空间, **可供线程共享**
  * 对于栈中的数据, **各线程独享**, 每个线程有独立的线程栈和栈指针[^csb-342]
* 对于同一个计算机, 即 Cpu 架构相同, 不同的操作系统对应的**系统调用指令相同**, 同一操作系统在不同计算机(Cpu架构)的**系统调用指令不同**, 根本原因是, Cpu 架构决定操作系统的传参, 而指令是一样的, 所以不同的操作系统传参是一样的, 系统调用相同而计算机不同, 则指令不同, 对应系统调用指令也不相同; **注: 一个计算机上, 不同的操作系统对应的系统调用接口不同, 注意区分接口与指令**[^csb-343]

#### 进程与线程 {#cs408-h-37}

* 一般情况下的进程优先级设置原则:
  * 系统进程 &gt; 用户进程
  * 交互型进程 &gt; 非交互型进程
  * I/O型进程 &gt; 计算型基础(防止数据覆盖, 尽早地开启 I/O 可以提高系统整体效率)[^csb-348]
* Cpu 时钟是处理器内部的基准时钟, 也称为节拍, 常见的时钟周期就是指的 Cpu 时钟; 而**时钟中断是由系统时钟发出的, 属于外中断,作用于操作系统**, 所以操作系统来控制系统时钟, 常用于调度, 时间片, 定时中断
* 使得一个进程终止的情况:
  * 正常结束
  * 异常结束, 发生异常, 使得进程无法继续进行
  * 外界干预, 由外界请求而终止, 如管理员或操作系统干预, 父进程请求或父进程终止等
* 各类型进程优先级比较: 中断处理程序 &gt; 实时进程 &gt; 交互型进程 &gt; I/O 型进程 &gt; 计算型进程 &gt; 后台(非交互)进程; 系统进程 &gt; 用户进程[^csb-354]
* 一个进程只有在特殊的内核约束下才不可被调度, 例如原语操作. 即使是进程处于临界区也是可以被调度/抢占的
* 若一个高优先级进程被创建后进入就绪队列, 此时抢占过程是这样的: 有新进程进入就绪队列, Cpu(或操作系统)查看其优先级, 若优先级高, 则停止当前进程, 进行 Cpu 调度, **该过程不需要中断参与**[^csb-356]
* 管程中条件变量不一定要遵循严格守恒, 即一个 wait 对应一个 signal, 但是管程中的 wait 函数一定是在**条件变量不够的情况下调用, 即一定引起进程阻塞**, 而 signal 函数则是看阻塞队列中是否存在进程, 若有进程则唤醒, 否则跳过
* 在互斥方法中, 信号量机制与管程适用于单线程和多线程(多 CPU), test-and-set 由于是原子操作, 仍然适用于多 CPU, 而关中断则不适用于多 CPU, 其他 CPU 仍可访问共享资源, 无法实现互斥
* 原子操作并不等于关中断再开中断, 原子操作是直接锁住总线从而禁止其他 Cpu 访问[^csb-359]
* Cpu 轮转算法的三个考虑因素: 系统的响应要求, 就绪队列的数量, 系统的处理能力; **各个进程的运行时间无法推算, 所以不采纳**[^csb-360]
* 若进程在执行的过程中发生了中断, 且此中断不是 I/O 中断, 即进程不会主动让出 Cpu, 那么此时 Cpu 进入内核态执行相应的中断程序, 这里的中断处理程序只是一段代码, 即 Cpu 只是进入内核态跑一段代码, 不是换了新的进程, 所以此时的进程状态仍然是运行态, 不一定会发生进程调度
* 进程间通信
  * 管道(pipe): 建立管道时, 系统文件表会新增两个表项, 两个进程用来控制文件读和写, 一个管道为单向, 若要同时读写需要建立两个管道, 管道之间的读写互斥同步是由管道进程来控制的[^csb-363]

### 内存管理与虚拟存储器 {#cs408-h-40}

#### 内存管理 {#cs408-h-41}

* **页表寄存器**保存的是**最外层页表的起始物理地址**, 即一级页表(**408把最外层页表称为一级页表**)的始值, 后面的多级页表的物理地址均在上一级页表项中存储; 由于每个进程都有各自独立的地址空间, 所以每个进程的最外层页表是不一样的, 即每次切换进程**一定导致页表寄存器内容变换**, 而切换线程则不会(线程共享内存空间)[^csb-381]
  * 注意与动态重定位寄存器区分, 分页分段(请求)存储方式也算为动态重定位方法, 单往往逻辑地址转物理地址时, 两者取一个即可, 对于分页方式, 一般用页表寄存器, 重定位寄存器更适合连续分配方式(分段方式);[^csb-382]
* 存储管理方式中, 进程在内存中的空间可以不连续的方式有: 分页式分配, 分段式分配(**将一整个作业分成若干逻辑段, 按需放入内存**), 段页式分配
* 计算 cache 或 TLB 命中率时, 即使是 1000 次中只有一次未命中, 也要计算, 不能直接约等于 100%
* 对于一个进程的访问, 具体的过程应该如下:
  * 首先查询 TLB, 若 TLB 中没有对应的页号, 则再访问内存中的页表(这里可以同时访问, 看题目要求), 若页表对应的页号有效位为 0 或无对应页框, 则需要访问外存, 然后再写入 TLB, 然后再重新从 TLB 查询页表(此过程中 TLB 查询了两次, 其实这里是缺页中断程序完成, 重新返回到原指令处重新执行, 所以会先查 TLB). **注意: 这里只是得到了对应的物理地址, 还需要进行访问内存操作! 计算时间的时候要格外注意**
  * 得到对应的物理地址后, 查询 Cache, 若 Cache 未命中, 则只能直接访问内存(可能同时访问), 然后再把对应的存储单元写入 Cache.
* 紧凑技术适合不固定大小的动态分配, 即适合动态重定位分区分配的存储管理方式

#### 虚拟存储器 {#cs408-h-42}

* 主存—外存（虚拟页 ↔ 物理页框）的映射是 **全相联** 的，原因是操作系统需要把任意虚拟页装入主存的任意页框以保证灵活性和内存利用率；映射关系由页表记录，TLB 用于加速这种映射的查找;
* MMU 是虚拟地址到物理地址的转换过程, 在转换过程中会检查访问权限, 以及是否越界等操作;[^csb-391]
* 对于请求分页式(或分段)存储系统与分页式存储系统不同的是: **前者是虚拟存储器技术, 常驻于外存, 需要缺页中断, 换句话说, 前者又可称为"虚拟分页式存储器", 所以可以逻辑上扩大内存空间**, 而普通(或简单)分页(或分段)存储系统是常驻内存的, 只需页表即可, 不会发生 "抖动(颠簸)" 现象;[^csb-392]
* 请求段式存储系统中段表对应的物理地址是基地址, 即计算真实的物理地址的方法应是: **基地址 + 段内偏移量**
* Cache 由硬件实现, 虚拟存储器由硬件和软件共同实现; 其中, 系统程序员可以看到虚拟存储器, 而应用程序员看不到, 透明;
  * 更深层次的, 仅系统程序员可见的(其实大部分与操作系统有关系的, 系统程序员均可见): **硬件细节**: PSW(状态字寄存器), 设备寄存器、指令系统、I/O 通道、DMA 控制器、中断向量表等; **内核数据结构与机制**: PCB（进程控制块）、就绪队列、阻塞队列, 页面表、段表、换页算法, 文件控制块（FCB）、索引节点（inode); **中断处理程序、驱动程序**[^csb-395]
* 若要划分具体的页, 整体的虚拟存储空间需要多少页, 需要知道一页可容纳多少个页表项, 然后利用这两者的关系求出具体的级数划分; 如"<mark>64位计算机, 地址线宽 64 位, 虚拟地址空间大小 ${2^{48}}$, 采用虚拟存储系统, 每页 4KB, 页表项长为 8B, 求多级页表的最小级次</mark>"; **答:** 虚拟地址为 48 位, 与物理地址空间大小无关, 共需要 ${48-12=36}$ 位容纳页号, 一页可容纳 8KB/8B=1K=10位 页表项, 所以最少只需要 ${36/10=3.6\Rightarrow 4}$ 级页表即可;[^csb-396]
* 在地址变化过程中, 可能产生缺页中断, 越界中断, 访问权限/保护中断(表明禁止执行、禁止写或禁止用户访问等；或段/页访问超出权限)
* 关于二级虚拟存储系统的计算问题, 这里举个例子
  * <mark>计算机采用二级虚拟页式存储，内存大小为 4MB，采用虚拟页式存储管理，进程的寻址空间为 256MB，页面大小为 1KB，页目录表和页的大小均为一个页， 且表项大小均为 2B，表项包含存在位和物理页框号以及访问权限位，其中最高位开始的连续 k 位为物理页框号，最低位为存在位，剩下的则全部为权限位。页表基址寄存器 PTBR 的值为 0x000C00H, 已知 P1 访问逻辑地址 0x2000400H，给出计算物理地址的过程</mark>; **答:** 内存 4MB, 22位, 由于一页占 10 位, 故物理页框号占 12 位; 虚拟地址占 28 位, 一页可以容纳 ${512 = 2^9}$ 个页表项, 所以二级存储虚拟地址格式为: 9(页目录) + 9(页号) + 10(Offset), 所以页目录号为 040H, 页号为 01H; 则先去找页目录对应的表项, 利用 PTBR 得到: ${000C00H+040H\times 2=000C80H}$ (这里乘 2 是因为页表项占 2B); **取 2B 的内容, 若目录项只有 1B, 则根据大小端方式取下边的对应目录项的值**, 这里假设得到 4523H, 则由于物理页框占 12 位, 最后一位为 1, 有效, 所以页表的物理地址为 ${452H\times 1KB}$, 页表所在的 1 号页的物理地址为 ${452H \times 1KB + 1 \times 2=114802H}$, 由此得到对应的物理页框;[^csb-399]

### 文件系统 {#cs408-h-43}

* 对于文件操作
  * open 操作需要指定文件路径或文件名, 然后会返回一个文件描述符, 即 `FILE *fp = fopen(const char *pathname, const char *mode);` 这里的 `*fp` 即为文件描述符, 以后的 read 调用就不需要再去外存检索目录了, 更迅速[^csb-404]
  * 删除文件用到的系统调用是 unlink, 与删除硬链接用到的文件调用是一致的, unlink 的参数是文件名，而不是文件描述符, 删除文件时要求 用户对这个文件具有"写"权限, 只有这个计数值为 0 时, 才释放文件占用的外存空间(包含文件的数据本身和文件的索引节点)[^csb-405]
* 关于读文件操作流程:
  1. 根据文件名(或文件描述符, 取决于是否读入)在活动文件表中找到文件对应的目录项[^csb-407]
  2. **按存取控制说明检查访问的合法性**
  3. 若要调取的文件数据不在内存, 进程进入阻塞状态, 等待内容读入内存. **注:** 若文件系统采用虚拟映射文件, 那么会产生缺页中断
  4. 根据目录项中文件的逻辑和物理组织形式, 将逻辑记录号转化为物理块号
  5. 向设备驱动程序发出 I/O 请求, 完成数据交换
* 文件系统中, 若需插入一个文件记录并计算磁盘块访问次数, 考虑不同的分配方式
  * 若为顺序分配, 如果要求最少的磁盘块访问次数, 此时应该**根据插入的位置决定将部分数组前移还是后移**, 例如 1000 条记录中插入到第 20 条, 明显的前移更好. **在移动的过程中, 每个磁盘块需要读、写一次, 即访问磁盘块两次**, 也就是将前 19 条记录读写两次, 然后再写入对应位置的磁盘块一次, 总计 ${19 \times 2 + 1 = 39}$ 次[^csb-413]
  * 若为链接分配, 则**必须从前往后读**, 即读 19 次, 然后找一个空闲磁盘块写入, 指向第 19 块磁盘的下一条指针, 再把第 19 块磁盘的指针指向对应磁盘块, 即**写 2 次(一次空闲磁盘, 一次第 19 块磁盘)**, 总计 ${19 + 2 = 21}$ 次
* 文件的多级索引技术中, 其索引节点是有大小的, 在计算最大文件大小的时候要综合考虑, 取最大数据容量和最大索引节点容量的较小者; 即若索引节点大小 64B, 一个簇 1KB, 用 1M 个簇存放索引节点, 512M 个簇存放文件数据, 那么系统一共有 ${\dfrac{1M\times1KB}{64B}=16M}$ 个索引节点, 而数据区有 ${512M \times 1KB=512GB}$, 故整体可存放最大文件大小为: ${min\{512GB,\,16M\times 1KB\}=16GB}$[^csb-415]
* 文件存储系统:
  * 连续分配需要在**进程控制块FCB**中记录其文件的其实物理块号和大小(或连续块数), 故无需用专有块记录;[^csb-417]
  * 隐式链接分配也需要在**进程控制块FCB**中记录其起始块号和末尾块号,也无需用专用块记录. **注:** 隐式链接分配中, 每个物理块都需要记录一个**下一块指针**, 所以其物理块可容纳的数据大小是较小的, 并且这种方式可容纳的磁盘块大小也是受限的(指针位数), 故文件大小受限;[^csb-418]
* 磁盘缓冲区类似于外部磁盘的高速缓存, 需要用到的页面可以从缓冲区获得, 即可以减少磁盘 I/O 次数
* 一定要注意 FAT 显示链接表中存放的是下一个簇的物理块号, 而不是本块号; 如 `一个簇 2KB, FAT 表中 B 文件对应的簇号链为: 5000 -> 4000 -> 4500, 问 B 文件的第 5000 个字节和第 9000 个字节对应的物理块号`: 一个簇 2048B, 所以两个字节分别对应第 2, 4 号簇, 故对应的物理块号为: 5000, 4500[^csb-420]
* 在文件储存技术中, 所谓文件存储方法(顺序, 隐式链接, 混合索引方式), **是针对单个文件的存储方法**, 也即: 顺序存储方法中, 文件的 FCB 需要记录文件数据的起始物理块号和长度; 链接方法中需要记录文件数据的起始指针和尾指针; 而(混合)索引方式中直接, 一级, 二级间址的目录项均在 `inode` 中, 所以这种方法可以计算出文件的最大大小, **注意:** 这种方法并不是整个外存空间的大小, 而是外村空间分配给文件的最大大小, 由此可知, 限制文件数量的因素取决于索引点数和外存空间能够放下多少个物理块;[^csb-421]
* 文件共享
  * 硬链接: 硬链接把文件的地址信息存放到共享的索引节点中, 各个进程访问该地址, 所以文件的增删改都是一起进行的, count 值也是同一个值[^csb-423]
  * 软链接: 只有文件拥有者才拥有指向其索引节点的指令, 其他只需要路径名即可, 同理也能共享增删改后的信息, 该方法只要有对应主机的网络地址以及文件路径就可以共享, 不必局限于一台主机[^csb-424]
  * 软链接由于新增加了文件存储路径, 所以会导致其开销较大
  * **所有链接共享方式**共有的一个缺点就是, 文件有两个或多个路径, 查找指定目录下的全部文件程序定位到多个符合的文件, 即复制多次同一份文件[^csb-426]
* 目录结构
  * 单级目录结构即只有系统目录, 所有用户使用一个目录, 实现了按名存取, 但速度慢不允许重名
  * 两级目录结构分为系统目录和用户目录, 但用户目录下不能再细分, 提高了速度, 解决了不同用户的重名, 可以实现访问限制
  * **以上两种方式导致用户不能对自己的文件进行分类管理**

### 外部设备与 I/O {#cs408-h-44}

* 设备分配的几个概念
  * 设备的静态分配：作业执行前，操作系统一次性分配该作业所需的全部设备、控制器和通道。一般用于独占设备。优点是能够预防死锁，缺点是降低了设备的利用率。
  * 设备的动态分配：当作业需要用到某一设备时，系统才会为其分配。一般用于共享设备。优点是提高了设备利用率，缺点是可能发生死锁。
  * 设备的安全分配：一个进程在同一时间段内只能使用一个设备。获得设备的进程立即进入阻塞状态，不能再请求任何资源。优点是能够预防死锁，缺点是同一个进程，CPU 和设备只能串行工作，进程推进效率不高。
  * 设备的不安全分配：进程在发出 I/O 请求后继续运行而不阻塞，需要新设备时可以继续发出 I/O 请求，仅当请求的设备已被占用时，才进入阻塞状态。优点是一个进程可同时操纵多个设备，使得进程推进迅速。缺点是可能导致死锁。
  * **设备的安全分配和设备的静态分配均是破坏了"请求和保持"**
* 为了实现独立性, 进程访问设备使用的是逻辑设备名(当然也可以用文件名访问物理设备), 这样操作系统可以根据逻辑设备名映射到物理设备表, 从而选择空闲的设备分配; 系统中有一张系统设备表(SDT), 其有个表项为设备类的驱动程序入口, 也就是如果更换物理设备, 只需要更换其驱动程序入口即可
* 缓冲技术: 主要为了**解决 CPU 速度和外设速度不匹配的问题**; 通道技术: 为了**解决 CPU 不必过多参与复杂 I/O 控制的问题, 不是单纯的速度不匹配** 提高 CPU 效率; 并行技术: 为了提高整机的运行效率和吞吐率; 虚存技术: 解决存储系统的容量问题; DMA 技术或其他中断 I/O 技术: 解决 CPU 和 I/O 数据传送效率低 的问题。
* 设备独立性软件与设备驱动程序各自的作用
  * 设备独立性用于实现**设备命名, 设备保护, 设备分配与释放**, 即用户申请使用逻辑设备名时, 由设备独立性软件进行设备分配, 将其映射为物理设备名, 禁止用户直接访问设备;
  * 设备驱动程序用于将命令和参数转化为具体要求(例如盘块号转化为盘面, 磁道, 扇区号); 检查用户是否有权限; 查询设备是否空闲, 若空闲则发出 I/O 命令, 给 Cpu 指明具体的中断服务程序入口或中断向量; 由于设备驱动程序需要对 I/O 设备进行控制, 所以不同的 I/O 方式(或不同的设备)对应不同的驱动程序
  * 将**设备名转为端口地址**由设备驱动软件负责, 设备独立性软件负责提供逻辑地址, 即 I/O 接口与通道的逻辑对象并且映射到相关驱动软件, 然后**由驱动软件负责映射(驱动可查询设备独立软件维护的设备表)**
* SpooLing 技术
  * 是设备独立性软件, 建立在多道程序设计基础上, 由系统(井管理程序)控制数据的传送
  * 输入进程和输出进行均运行在内核态, 当输入井或输出井无数据且无输入或输出任务时, 对应的输入/输出进程进入阻塞态, 两者可以并发执行[^csb-446]
* 通道的工作过程: **1.** Cpu 要操作 I/O 设备, 向 I/O 通道发出命令, Cpu 忙别的事情; **2.** I/O 通道去内存找到相关通道程序; **3.** 启动 I/O 通道, 然后进行 I/O, 组织 I/O 操作; **4.** 向 Cpu 发出中断信号告知已经完成;
* I/O 管理与设备管理的功能: 能实时掌握外部设备的状态, 可以实现存取操作, 负责对设备的分配与回收, 对设备的驱动、完成和故障的中断处理, 进行虚拟设备(Spooling技术);

### 系统性的总结 {#cs408-h-45}

#### Scenario 1 - 应用程序执行环境 {#cs408-h-46}

>本场景描述从磁盘被制作出来开始，到形成应用程序正常执行的环境的全过程。磁盘想要被正常访问，需要对磁盘的存储空间进行编址，通过特定的操作，磁盘的物理空间被划分为不同的柱面、磁盘和扇区。[^csb-452]
当可用的磁盘被接入计算机主机中后，计算机便可以通过物理磁盘名+磁盘地址的方式访问到特定磁盘的特定地址。但是，为了灵活使用，我们往往会把整个物理磁盘空间划分为 逻辑上的多个空间，类似于 windows 系统中常用的 C 盘、D 盘等区域，不同的逻辑空间被称为不同的逻辑磁盘，也叫做不同的分区。
此后，根据具体需求，计算机在不同的逻辑磁盘上适配不同的文件系统，此后，不同逻辑磁盘上的文件系统还可以通过虚拟文件系统 vfs 层来进行相同格式的访问。
在上述处理过程中，我们会在物理磁盘的第一个扇区建立MBR，即主引导扇区，并在每个逻辑磁盘的第一个扇区建立 PBR，即分区引导扇区。其中操作系统的代码和数据存放的 逻辑分区被称为主分区。[^csb-455]
计算机加电后，PC 会被设置为一个初始值，PC 指向的区域被称为 BIOS。BIOS 完成了计算机开机后需要做的最基本的初始化工作后，便从磁盘中加载了MBR 并执行。MBR 根据用户选择的操作系统去加载对应的主分区 PBR，再通过 PBR 把对应的操作系统加载到内存中，并把 CPU 控制权转交给新载入的操作系统。[^csb-456]
随后，操作系统完成一系列初始化工作，并启动了图形界面相关的程序，将图形界面展现在了用户面前。用户通过图形界面点开了一个可执行文件，程序开始正式执行为用户提供服务。

##### 场景二：进程控制块与进程调度 {#cs408-h-49}

>这个分场景分析 PCB 是如何参与到进程调度的过程中的，在这个过程中的全部场景都是单 CPU 单核操作系统，也就是说同一时间只有一个进程能够占用 CPU。进程调度的触发依赖 PCB 中存放的信息。
首先，操作系统会维护一个全局变量 current（在不同的 os 中可能实现不同，这里主要介绍原理性的内容），来指向当前进程的 PCB，通过访问 current，操作系统可以获取当前进程的全部信息。每次发生特定的中断或异常时，操作系统都会对 current 进程进行分析，从而判断是否应该发生进程调度。
在时间片轮转法中，进程 PCB 中会维护代表进程时间片的变量 time_slice，当处理时钟中断时，os 会将当前进程的 time_silce 减 1，若 time_slice 减少为 0，则当前进程理应被抢占 CPU，触发进程调度。[^csb-488]
在抢占式的优先级调度算法中，若操作系统发现一个进程被创建完成或某个进程从阻塞态转变为了就绪态，则应该对新就绪的进程与 current 进程的 priority 进行比较，若当前进程优先级较低，则应该触发调度，而 priority 也存放在进程的 PCB 中。
在协作式调度设计中，进程可以通过特定的系统调用主动放弃 CPU，从而完成各进程共同使用 CPU 资源。在现代操作系统中，通常协作式调度和抢占式调度是同时存在的，也就是说，进程既可以主动放弃 CPU，也可能因为特殊时间的触发被抢占 CPU。
**进程调度中新进程的筛选依赖 PCB。**
当当前进程需要调度时，进程会从就绪进程队列中选出一个合适的 PCB 作为新的 current 进程来使用 CPU。若采取优先级调度算法时，会选择优先级最高的进程来占据 CPU。 若采用多级反馈等调度算法时，不同优先级的进程会组织成不同的就绪队列。
**进程切换也需要 PCB 的参与。**
当进程发生切换时，操作系统会利用 current 进程的 PCB 和待切换进程的 PCB 来实现上下文的切换。 进程上下文的主体是断点和各通用寄存器的值，发生进程切换时，操作系统会把当前的 pc 值和通用寄存器的值保存到 current 进程的 PCB 中，再从新进程的 PCB 中取出断点值和 寄存器值装入各寄存器中，从而实现上下文的切换。 进程切换同时需要地址空间的切换，在页式内存管理中，页表基址寄存器 PTR 的值决定了逻辑地址向物理地址的映射关系，而 PCB 中会保存各进程所对应的页表的 PTR 的值。 当发生进程切换时，操作系统会把 PCB 中保存的 PTR 值放入页表基址寄存器中，从而实现 地址空间的切换。
同时，我们知道不同的进程拥有不同的用户栈和内核栈，发生进程切换时理应也伴随者堆栈的切换，因此 PCB 中同样保存着进程的用户栈和内核栈地址来保证堆栈切换。 基于以上描述，请回答下列问题：

* 帧长度最大为 1518 字节, 其中有效数据部分最大为 1500 字节, 最小为 46 字节(MAC帧占 18 字节)[^csc-713]
* 波特率 B 与数据传输率 C 的关系: ${C=Blog_2N}$, N 为一个码元所取的离散值个数, 一个码元代表一个不同的状态, 可以理解为 ${x}$ 码元为 ${x}$ 进制[^csc-714]
* 各个协议对应的网络体系:
  * 链路层:PPP、HDLC、CSMA
  * 网络层:ARP、ICMP、IP、OSPF
  * 传输层:TCP、UDP
  * 应用层:DHCP、RIP、BGP、DNS、FTP、POP3、SMTP、HTTP、MIME
* 对于 Http 传输, 首先应该建立 TCP 链接, 此时需要 1.5 个 RTT, 而第三次握手, 即 0.5 个 RTT 可以用于传输数据, 所以若要请求一个网页, 则需要 2RTT 即可[^csc-720]
  * 注意需要传输的顺序, 一定是**先建立TCP再进行页面响应, 要观察报文段, TCP 连接的 SYN 字段, 若不为 1, 则证明已经建立好 TCP 了, 故 Web 请求只需要 1RTT**[^csc-721]

  * 关于 http/1.1 的非流水与流水线方式, 由于是持续的连接, 所以对于非流水就是一个请求花费一个 RTT, 而流水线则是多个请求花费一个 RTT
* 关于 IP 数据报在传输路径上的可变字段, 有如下总结:
  * **若是私网, 则需要经过 NAT 转换**, 此时路由器若为**发送方需要修改源地址 IP, 接收方需要修改目的 IP**[^csc-725]
  * 每经过一个路由器就修改其 TTL 与头部校验和字段
  * 考虑不同链路的 MTU 不同, 故可能修改: 总长度、标识、标志、片偏移、FLAG标志(MF, DF)[^csc-727]
  * 移动 IP 过程可能改变目的 IP
* **数据链路层既可以提供可靠服务，也可以提供不可靠服务**，取决于具体协议和工作模式。
  * 例如 **Ethernet MAC（以太网）**：典型实现是 **无连接、不可靠**（只是检测 CRC，出错就丢帧，不重传）。
  - 例如 **HDLC/PPP 的有确认模式（带序号和 ACK 的模式）**：可以提供 **有连接且可靠** 的链路服务（使用 ARQ、窗口等）。[^csc-731]
  - **802.11 无线 MAC** 对单播帧有帧级 ACK 和重传，所以在 MAC 层对单播帧可以算作**有一定可靠性的传输（是面向帧的"可靠"）**。
* 以太网交换机的两种工作模式
  * 直通交换方式: 立即按目的 MAC 帧转发接口, 时延小, 不检查差错, 由于**只检查目的 MAC, 故只处理 6B 的数据**
  * 存储转发方式: 缓存帧, 检查帧, 时延大, 可靠, 由于需要检查差错, 所以**处理的是一个以太网帧, 即至少 64B 的数据**[^csc-735]
* 路由表中可以出现类似 128.20.96.0/23 和 128.20.96.128/25, 因为转发时遵循掩码最优原则
* 路由协议中, RIP 是应用层协议, 利用 UDP 传输; OSPF 是网络层协议, 利用 IP 传输; BGP 是应用层协议, 利用 TCP 传输;
* **时延带宽积是任意时刻在信道传输的最大比特数**, 时延带宽积 = 传播时延 ${\times}$ 信道带宽, 表示信道能够容纳的最大比特数
* 香农定理, 奈奎斯特, 信噪比
  * 香农定理: 信号传输速率 = ${Wlog_2(1+S/N)}$, W 为频率带宽, S(信号功率)/N(噪声功率) 为信噪比, S/N 可采用分贝(db)记法, 如 S/N = 1000, 则为 ${10\times log_{10}(S/N)=30dB}$;[^csc-740]
  * 奈奎斯特定理: 信号传输速率 = ${2Wlog_2V}$, W 为带宽, V 为码元数;[^csc-741]
  * **区分信道的传输和传播: 传输是信号的发送速率, 传播速率是信号在信道上的传送速率**
  * 信噪比越高, 信号功率越大, 其传输的码元的分到的能量也就越大越稳定, 于是传输错误率下降[^csc-743]
  * 对于**信噪比一定**的情况下, 传输率越小, 那么每个码元分到的能量也就越大越稳定, 同上
* 数据链路层的可靠传输机制(ARQ协议)中窗口大小与注意事项
  * 单帧滑动窗口, 停止等待协议(S-W): 发送与接收窗口大小均为 1
  * 后退 N 帧(GBN)协议: 设采用 ${n}$ 比特编码方式, 则接收窗口大小始终为 1, 发送窗口大小为 ${1\lt W\leq 2^n-1}$
  * 选择重传(SR)协议: 设采用 ${n}$ 比特编码方式, 发送与接收窗口设为 ${W_T、W_R}$, 则有 ${1\lt W_R、1\lt W_T、W_R+W_T \leq 2^n}$, **但注意**, 若发送窗口小于接收窗口, 那么接收窗口一定不满, 若发送窗口大于接收窗口, 那么接收窗口一定丢弃一部分, 所以最好 ${W_R=W_T}$, 因此有: **接收窗口最大值 ${W_T=2^{n-1}}$**[^csc-748]
  * 注意事项: **在计算信道利用率时, 分子上面的 ${n}$ 是 ${n}$ 个分组, 即 ${W_T}$**
* CSMA/CD 协议中的 ${\tau}$ 是两个主机的最远相距时长, 若要确认无误, 则要计算上发生碰撞之后返回错误信息的时间, 即为**争用期** ${2\tau}$, 而这个传输时延也是在协议中的最小 ${RTT}$ 时延. 若在传输过程中有其他设备的延迟, 此时的争用期可缩短, 考虑一个 100BaseT 的设备, 由于以太网的最短帧长为 64B, 那么争用期即为 ${64B/100Mbit=5.12\mu s}$, 此时若有其他设备的时延 ${\Delta x\mu s}$, 那么其**单向传播时延可写为 ${5.12 \mu s/2 - \Delta x \mu s}$**, 此时可根据信号传播速度确认两者距离(**注意这里要换算成单程传播时延, 因为争用期(最短帧长)是按照一个来回计算的**)[^csc-750]
  * `一个采用 CSMA/CD 的网络中，信号传播速率为 200m/us, A，B 两个站点中间位置新增一个 100BASE-T 的直通式交换机，则理论上 A，B 两个站点之间的最远距离可缩短多少m`: 由于采用直通式交换机, 只需检查目的 MAC 的 6 字节, 即 48 bit, 耗时 0.48us, 所以单向传播时延最少可缩减到 ${2.56us-0.48us=2.08us}$, 故距离为 ${416m}$, 则 ${\Delta x=512m-416m=96m}$[^csc-751]
  * `主机A和B连接在 800m 长的电缆线两端，并在 t=0 时各自向对方发送一个帧, 长 1500bit (包括首部和前同步码).A和B之间有4个转发器, 在转发帧时会产生20bit的时延. 设传输速率为1OOMbit/s, 而 CSMA/CD 的退避时间是 r 倍的争用期, 争用期为 512bit, 在发生第一次碰撞后, 在退避时A选择 r=0, B选择 r=1. 信号的传播速率是 200000km/s, 求 B 完全收到 A 发送的帧的时间`: 传播时延为 ${\dfrac{800}{2\times 10^8}=4\mu s}$, 转发器时延为 ${4\times \dfrac{20bit}{100\times 10^6}=0.8\mu s}$, 总传播时延为 ${4.8\mu s}$, 发送一帧的传输时延为 ${\dfrac{1500bit}{100Mb/s}=15\mu s}$.[^csc-752]
    1. ${t_0=0}$ 时, A, B 同时发送
    2. ${t_1=4.8\mu s}$ 时, 双方均受到对方的第一个 ${bit}$, 发现冲突, 停止发送进行回避, 此时双方已经传输了 ${t_1}$ 时间的数据了, 因此信道上还有数据
    3. ${t_2=4.8+4.8\mu s}$ 时, B 的最后一位数据到达 A, A 此时监听信道无冲突, 根据 ${r=0}$ 立即重传
    4. ${t_3=t_2 + 4.8 \mu s}$ 时, A 的第一位达到 B, 由于争用期 ${5.12\mu s \lt  4.8\mu s}$ 此时 B 还在回避, 于是 B 发现冲突不发送数据[^csc-756]
    5. ${t_4=t_3+15 \mu s}$ 时, A 的最后一位到达 B
    6. ${t_4}$ 之后, B 此时回避时间已过, 且信道无冲突, 于是发送数据给 A
* TCP 相关
  * TCP 报文中的序号是以 **字节** 为单位的, 即若 MSS = 1KB, 那么发送 2MSS = 2KB 的数据其序号就要增加 2K
  * 对上述的单位要敏感, 例: <mark>数据传输速率是 2.5Gb/s, 假设 PDU 的生存时间为 51.2s, 若要尽可能地传送数据, 问 PDU 首部序号字段长度的最小设置为多少位?</mark> 传输过程中可承载的最大数据量为两者相乘得到 ${2^{37}b}$, 由于以字节为单位, 所以至少要 ${2^{34}B}$, 即 ${34b}$[^csc-761]
  * 在 TCP 拥塞控制中, 拥塞窗口是**接收一个确认报文就加一**[^csc-762]
  * 在 TCP 的连接建立和连接释放的过程中, **TCP 连接只有握手第一个报文 ACK 可以不为 1**, 其余字段的 ACK 均为 1
  * TCP 共设置了四种计时器, 分别为: **超时重传计时器**, **持续计时器**(当接收方的窗口大小为 0 时, 为了避免死锁等待, 发送发会根据持续计时器来间断的询问窗口大小), **保活计时器**(当客户机出现故障, 保活计时器可避免服务器的一直等待), **时间等待计时器**(TCP 挥手协议中的 Time_Wait 时段, 大小为 ${2\times MSL}$)
* 不要忘记域名服务器 DNS 也有缓存, 可以不用向根域名服务器查询
* 在 GBN 协议中, 对方的发送的序号是一个一个接收的, 设数据帧形式为 ${R_{x,y}}$ 其中 ${x}$ 代表自己的数据帧序号, ${y}$ 代表确认帧即希望收到的下个序号,若分别收到了 ${R_{2,\,2}}$ 和 ${R_{4,3}}$, 那么此时我们要给对方发送的是 ${R_{3, 3}}$ 即**希望收到 3 号数据帧, 而不是 5 号数据帧**
* 关于 ARP 协议中 MAC 地址的确立
  * ARP 协议只用于本网络内, 即若同属于一个网络的 H1 向 H2 发送数据, 那么其 MAC 目的地址为 ${MAC_{H2}}$, 而若向其他网络的主机 H3 发送, 则直接交给默认网关, 也即目的地址为 ${MAC_R}$, 此时的任务由 R1 来完成(**若 R1 与 H1 的网段是 NAT, 那么还需要更换其源 IP 地址**)
  * 若 H3 在与 R1 相连的网段中(即 R1 路由表内下一跳是 --- 的网络), 那么 R1 就把数据帧的目的物理地址封装成 ${MAC_{H3}}$; 否则查路由表决定自己的下一跳, 然后目的物理地址封装成对应的路由器 ${MAC_{R2}}$
  * 以此类推, 直到目的主机收到 ARP 请求报文, 然后目的主机发送 ARP 返回帧, 这个返回帧是只返回给发送自己的一方, 即 H2 向 H1 发送, H3 向 R1 、R1 向 H1 发送, **此时 H1 收到的是 R1 的返回帧, 而不是 H3**[^csc-770]
  * **注:** 上述过程中, 不在同一子网内的主机的 ARP 过程并不是一气呵成的, 因为主机 H1 根据目的 IP 地址判断不与目的主机 H3 在同一个子网, 所以直接 ARP 默认网关的 MAC, 转交给默认网关(路由器), 然后接下来就是默认网关 ARP, 依次递进

  * 地址划分时若题目中给出若干子网信息, 需要根据子网号进行划分, 例如给出四个子网: 子网1: 130.130.19.0, 子网2: 130.130.20.0; 子网3: 130.130.11.0; 子网4: 130.130.12.0; 由于子网号中主机号为全 0, 所以需要划分到 255.255.255.0 才行;[^csc-773]

* 关于主机 H 从初始情况访问一个 Web 服务器(`www.bilibili/o-Sakurajimamai-o/home.com`)的相关过程
  * 若主机 H 需要 IP 地址, 则需要进行 DHCP 配置 IP 地址, 期间进行 DHCP 发现报文(H 向服务器发送 MAC 广播, 源 IP 为 0.0.0.0), DHCP 提供报文(服务器向 H 发送 MAC 单播, 源 IP 为服务器IP, 但目的 IP 仍为 255.255.255.255), DHCP 请求报文与 DHCP 发现报文类似, DHCP 确认报文与 DHCP 提供报文类似; 此过程是基于客户/服务器, 传输层用 UDP 封装; **补充:** DHCP Offer 报文中包含 <mark>主机申请、DHCP、默认网关、DNS 等的 IP 以及子网掩码</mark>[^csc-777]
  * 若主机要访问 `www.bilibili/o-Sakurajimamai-o/home.com`, 首先需要获取本地域名服务器的 MAC 地址, 即使用 ARP 协议进行广播, 通过交换机转发(若有, 更新相关设备表), 得到相关 MAC 地址后查询本地域名服务器, 这个过程不计入 DNS 访问次数, 本地域名服务器也有间隔更新缓存, 若缓存中有, 则直接返回, 否则查询: 根域名服务器、 com域名服务器、 .bilibili域名服务器, 即查询 3 次 DNS; 此阶段用到的协议是 DNS 协议, 传输层用 UDP 封装, 网络层是 IP 协议, 数据链路层是 CSMA/CD 协议(以太网V2帧)[^csc-778]
  * **注:** 在上面的域名解析过程中, 主机**只需要发送一次 DNS 请求**, 而本地域名服务器(DNS), 根据自己的缓存和查询方式, 若有缓存, 则无需发送 DNS 请求; 若采用递归查询, 则只需发送一条给根域名服务器; 若为迭代查询, 则需要发送 3 次 DNS 请求[^csc-779]
  * 得到了具体的 IP 地址后, **还需要得到默认网关(R1, 假设 Web 不在子网内, 若在, 则请求的是 Web) 的 MAC 地址**, 故仍需再次发送 ARP 请求报文, 得到 MAC 后才可以向 Web 服务器发送 Http 请求报文, 通过交换机和路由器转发(更新相关设备表, 若路由器是 NAT 路由器, 则源 IP 地址需要更改), 使用 **TCP** 建立连接, 连接的过程中第一、二次握手不交换数据, 第三次握手捎带对资源的请求, 然后服务器发送资源和确认号, **这个过程花费 ${2RTT}$**(注意: 本质是传输 .html 文件的大小(这里设为不大于 1MSS), 受到 TCP 流量控制窗口的约束, 可能需要更长的 RTT, 看具体题目要求), 此时 H 会显示出网站的相关页面; 此阶段用到 HTTP 协议, 传输层用 TCP 封装(**注意 HTTP 本身是无连接的, 即不需要先建立 HTTP 连接, 但需要建立 TCP连接**), 网络层是 IP 协议, 数据链路层是 CSMA/CD 协议[^csc-780]
  * 上面整个过程, DNS 共收到 3 个与这次传输相关的帧, 分别为: `请求 DNS 的 MAC 的 ARP 广播帧`, `询问 Web 的 MAC 单播帧(DNS请求报文)`, `请求默认网关(若 Web 在子网内则为 Web) 的 ARP 广播帧`[^csc-781]
  * H 与 Web 传输相关数据, 期间受到流量窗口约束和 http 协议不同约束(比如 http 1.0/1.1, 持续/非持续, 流水/非流水等)
  * H 与 Web 断开连接, 进入 TCP 连接断开阶段
* UPD 检验和计算和 IP 检验和类似, **16位加法**, 但是 IP 只计算首部, UDP 计算首部和数据部分; **发送方:** 检验和字段放入全 0, 数据部分不够偶数个 0 就填一个 0(伪首部和这个 0 均不发送), **计算这些和(注意回卷)**, 然后**取反**发送; **接收方:** 加上伪首部和可能的 0, 然后相加(注意回卷), 若为全 1, 则无差错;[^csc-784]

* 网络的本地广播是 32 个 1, 即 IP: 255.255.255.255, 此为**本网络广播IP**, 即有限的广播, 其可以在内部广播, 至于这个的作用, 要对比直接广播; 直接广播: 子网号 + 主机号全 1, 即常见的广播分组, 如 xxx.xxx.xxx.255/24 等, 直接广播与本地广播的本质不同是**直接广播可被路由器转发, 可被外部截获, 降低了网络安全性**;[^csc-786]
* 在 CSMA/CD 中, 发送端检测到冲突并停止之前, 可能已经发送出去的比特数称为**最大碎片帧长度**, 其值正好等于 **在 2τ 时间内最多能发出的数据量**, 也就是说以太网中的最短帧长必须不能小于这个长度; **关于为什么需要最小帧长:** 发送速率为 R，那么在 $2\tau$ 时间内最多能发出的比特数为 ${R\cdot 2\tau}$。为保证发送方在发生冲突时仍在发送（能检测到冲突), 如果帧太短，发送方可能在冲突返回之前就发送完并认为发送成功，导致**未检测到冲突而产生错误数据**;

* CSMA/CA 无线局域网
  * CSMA/CA 采用这样的传输过程: 若信号站要发数据, 监听信道, 若信道空闲, 则**等待 DIFS 时间段**后直接发送整个数据帧. 否则检测到冲突, 需要进行退避, 以下情况必须使用退避算法: `1.发送第一个帧之前检测到信道忙, 2.每次重传, 3.每次发送成功后要发送下一帧`, 然后等待上一个站点发送完数据帧(DIFS + 传输时延 + SIFS + ACK 传输时延)之后, 此时检测信号空闲, 首先等待一个 DIFS 之后, 选取退避间隙时间, 退避间隙数 ${cnt}$, 第 ${k}$ 次退避选取的时间为 ${[0,\,(2^{4+k}-1)]}$ 随机选择(最大范围和 CSMA/CD 相同均为 1023), 然后进行 ${cnt}$ 次退避, 全部执行完后才发送数据帧, **在退避过程中若检测到有数据发送, 此次退避不计入计数**[^csc-801]
  * 退避算法除了检测到信道空闲之外, 其他情况**均要使用**退避算法, 包括
    * 在发送帧之前检测到无线信道处于忙状态
    * 在每一次**重传一个帧**时或在每一次**成功发送后要连续发送**下一个帧时
  * 所以当站点成功发送一个数据之后, 要继续发送下一个数据, 所做的任务应该是: **等待 DIFS 并退避一个随机时间后重新争用信道**
  * 上述过程中, 每个要发送数据帧的站点都会通过源站通知信道上的站点, 告诉自己要占用的信道持续时间(包括 ACK 返回时间, 这也是为什么检测到冲突后要在上面的那个时间段再发送), **这个过程并不是预约机制特有**
  * 例题: `DIFS 为 128 us, SIFS 为 28 us, ACK 帧长 2B, A、B、C 三个站点均要发送 100B 的数据帧, 信道数据传输速率 8Mb/s, t = 0s 时 A 计划发送, t = 50us 时, B、C 同时计划发送, 退避时隙为 20us, B、C采用的退避时隙数分别为 3, 5, 求 A, B, C 各自完成数据发送的时间`: A 检测信号, 空闲, 直接发送, 用时 DIFS + 传输时延 = 228us, 之后经过 SIFS + ACK传输时延 = 258us 后, B 检测空闲, 经过 DIFS 时间后, B、C 进行退避计数, B 经过 ${3\times 20=60\mu s}$ 先完成退避, 之后直接发送, 经过传输时延(100us) 后, 此时为 t=546, B 完成传输, 经过 SIFS 和 ACK传输时延, 即 576us 后, C 检测空闲, 进行 DIFS, 然后把剩余的两次退避计数用掉, 最终在 t=844us 时完成数据传输

* 快速重传机制(冗余 ACK)技术中, 是接收方每收到一个报文就立刻发送一个 ACK, 所以若接收方收到了失序的报文, 每收到一次就会发出一个 ACK, 比如发送方发送了 0~10 号数据报, 若 5 号数据报丢失, 则接收方收到 `6, 7, 8` 号报文时会发送三个 ACK, 而这个 ACK 信息都是一样的(${ACK_{seq}=5}$), 所以接收方收到了三个冗余 ACK 后会重发 5 号数据报, 而若丢失的是 8 号报文, 则 `9, 10` 号数据报只能让接收方发送两个冗余 ACK, 故无法做到快速重传[^csc-808]

* VLAN
  * 将局域网分割成多个广播域, 一个 VLAN 是一个广播域, 由于 VLAN 本身是交换机的原因, 所以其分割冲突域, 即 ${n}$ 台主机有 ${n}$ 个冲突域[^csc-818]
  * Vlan 相比于以太网帧, 由于 802.1Q 帧需要指明 4B 的 VLAN 标签号, 所以帧数据字段最小从 46B 变为 42B, 并且最大帧也从 1518B (1500 数据 + 18 MAC) 变到 1522 B
  * VLAN 的工作原理:
    * **"打标签"（Add Tag）：** 当一个帧要**离开**一个 **Trunk 端口**，并且该帧的 VLAN ID **不等于** 这个 Trunk 端口的 PVID (Native VLAN) 时，交换机必须给它打上 802.1Q 标签。[^csc-821]
    * **去标签"（Strip Tag）：**
      - 当一个帧要**离开**一个 **Access 端口**时，无论它是什么 VLAN，都必须去掉标签，以普通 MAC 帧发送给主机。[^csc-823]
      - 当一个帧要**离开**一个 **Trunk 端口**，并且该帧的 VLAN ID **等于** 这个 Trunk 端口的 PVID (Native VLAN) 时，交换机必须去掉标签（或不打标签），以普通 MAC 帧发送。
    * 各个主机的接口类型通常设置为 **Access**，并为其配置一个 **PVID**（例如 PVID 10），这代表该主机属于 VLAN 10；而交换机之间的接口设置为 **Trunk**。当主机 H1 (VLAN 10) 发送**普通 MAC 帧**（Untagged 帧）时，交换机 S1 从 Access 口（PVID 10）收到该帧，立即将其在内部归类为 VLAN 10。S1 查找 VLAN 10 的 MAC 地址表：若目的主机在 S1 的另一个 PVID 为 10 的 Access 口，S1 会"去标签"（确保是普通 MAC 帧）后直接转发；若该帧为广播帧或目的 MAC 在另一台交换机 S2 上，S1 需要通过 Trunk 口转发。Trunk 口也有一个 PVID，称为 Native VLAN（假设为 PVID 1）。此时 **S1 会判断帧的 VLAN ID (10) 是否等于 Trunk 口的 PVID (1)**：因为 10 不等于 1，S1 必须"打上标签"，以 802.1Q 帧（VID=10）的形式发送。只有当 S1 要发送的帧属于 Native VLAN (VLAN 1) 时（即帧的 PVID  等于 Trunk 的 PVID），S1 才会"去标签"，以**普通 MAC 帧**形式传输。**因此，交换机之间不一定只传 802.1Q 帧。** 最后，当 S2 收到这个 802.1Q 帧，它会读取标签知道这是 VLAN 10，如果要转发给 Access 口的主机，S2 也会执行"去标签"动作，将普通 MAC 帧发给主机。 更详细的知识可看湖科大 T35: [2022 408考研计算机网络模拟题03答案及解析](https://www.bilibili.com/opus/596286729367485481)

* FTP 存在主动模式与被动模式, 默认情况下为主动模式, 主动模式是 FTP 服务器向客户机建立连接, 即若 TCP 连接释放时, Time-Wait 计时器应该在 FTP 端等待, 即 FTP 应等待 2 x MSL 的时间后才会进入 CLOSED 状态.[^csc-827]
* 一个码元可以携带若干比特数, 但是曼彻斯特编码具有特殊性, 一次高低电平来表示一个比特, 所以曼彻斯特是用两个码元传输一位比特
* 边界路由器(eBGP, iBGP)在交换信息时要先建立 TCP 连接

[^csc-773]: **勘误或条件说明：** 给出的地址可以约束掩码，但仅凭这些网络地址不能唯一确定掩码。/24 是一种可行选择，更长前缀也可能有效；应结合主机数量、等长/变长划分等题设条件。

[^csc-774]: **勘误或条件说明：** 转发表中的目的字段通常是网络前缀，也可以是 /32 主机路由或 /0 默认路由，不限于普通子网地址。

[^csc-775]: **勘误或条件说明：** 虚电路并不天然保证可靠交付，也并非一定不分配带宽。是否预留资源、提供确认重传或其他可靠性保证由具体虚电路技术和服务决定；按已建立路径用标识转发与可靠性是不同性质。

[^csc-777]: **勘误或条件说明：** DHCP Offer/ACK 可按客户端状态和广播标志等条件采用广播或单播，不能固定记为 MAC 单播但 IP 目的地址总为 255.255.255.255。Offer 中还应区分分配给客户端的地址、服务器标识及网关/DNS 等配置选项。

[^csc-778]: **勘误或条件说明：** 示例字符串含斜杠，不能作为一个完整 DNS 主机名解析；DNS 解析 URL 的主机部分。只有 DNS 服务器在同一子网且 ARP 缓存未命中时，才直接 ARP 它的 MAC，否则应解析下一跳 MAC。根→顶级域→权威服务器三次查询只是特定无缓存模型；DNS 也可用 TCP，现代全双工交换式以太网不使用 CSMA/CD 争用。

[^csc-779]: **勘误或条件说明：** 真实根 DNS 服务器不为普通客户端提供递归解析，通常返回转介，由递归解析器继续迭代查询。课本中的纯递归示意应与实际部署区分；实际查询次数取决于缓存、委派层级及别名等因素。

[^csc-780]: **勘误或条件说明：** HTTP 通常说是无状态协议，不能因此说传输层无连接；HTTP/1.x 通常使用 TCP，HTTP/3 使用 QUIC。ARP 缓存命中时无需每次重发 ARP。这里的 2RTT 仍需遵守理想化假设，页面传输时间还受拥塞窗口、接收窗口、资源大小等限制。

[^csc-781]: **勘误或条件说明：** DNS 请求查询的是域名对应的 IP 地址或其他 DNS 记录，不是 Web 服务器的 MAC 地址。DNS 服务器恰好收到这三个帧，还依赖它与 H 同广播域、ARP 缓存为空等图示条件，不能推广为固定数量。

[^csc-784]: **勘误或条件说明：** UDP 校验和覆盖伪首部、UDP 首部和数据。补零条件是数据字节数为奇数，应在计算时补一个零字节，而不是判断零的个数。接收校验全 1 表示未检测到错误，不保证绝对无差错；IPv4 的 UDP 校验和字段为 0 还可表示未使用校验和。

[^csc-786]: **勘误或条件说明：** 定向广播在地址语义上可指向远端子网，但现代路由器默认禁用 IPv4 定向广播转发，只有显式允许时才会转发。安全问题主要涉及广播放大等滥用，不能简单等同于一定会被外部截获。

[^csc-790]: **勘误或条件说明：** 8 字节对齐要求针对 IPv4 非最后一个分片的数据部分长度，不是整个 IP 数据报长度；最后一片的数据长度可以不是 8 的倍数。片偏移以 8 字节为单位。原始数据报超过出接口 MTU 时，源主机也可能需要分片，且同样遵守这一规则。

[^csc-810]: **勘误或条件说明：** 使用同一个外地代理的多个移动节点可以共享该代理的 care-of address，不是说不同外地代理的 IP 地址可以任意重复。代理依据登记/访问者绑定关系完成解封装及向移动节点交付，最后一跳可能再使用 MAC 地址。
