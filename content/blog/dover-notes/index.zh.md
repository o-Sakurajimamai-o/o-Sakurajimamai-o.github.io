## 存在的问题
Who&When（WW） 的数据集评测方式其实是有问题的，WW 的具体表现形式为：

1. 输入：一份完整的失败会话日志，记录了从用户提问开始，多个智能体按轮次交互，直到最终给出错误答案（或触发最大重规划轮数等停止规则）的全过程。
2. 任务要求：让大模型阅读日志，找出导致任务失败的最早的、唯一的一个责任智能体和唯一的一个步骤。
3. 决定性错误步的定义：如果把智能体在这一步的错误动作替换成正确动作，后续的轨迹就能顺利走向成功。
但是作者发现，对于 WW 数据集中的轨迹，并没有表明步数，也就是每一步都需要大模型去记忆推断；同时交给 LLM 的判罚尺度与专家标注的尺度不一致，给 LLM 的 Prompt 里面嵌入了给人类专家的一句简介的指南提醒 `明确告诉模型：要找的是最早导致任务偏离正轨、且若修正就能成功的决定性步骤`。
完成以上两步后，在包含标准答案的 WW 手工构建集上，GPT-4o 的步骤归因准确率就从原来的 6.04%飙升到了23.56%。
继续往下探索，WW 数据集的归因方式或者说归因角度太过于单一，对于多种错误中挑选出一个绝对错误本来就是不确定的，这导致 LLM 可能与人类专家标注的不一致，但其实两者都可被认为是关键错误；多智能体还会存在智能体之间的责任模糊，即子智能体出错，可能是自身问题、也可能是分配任务的智能体描述不当造成，在这种情况下，只把错误归因于一个智能体是片面的。

## Dover
针对于以上问题，作者提出了 Dover，核心框架可简要说明为三个部分：

1. 撇弃人类专家标注的 GT，因为可能存在多视角错误（类 MP-Bench），Dover 回到了决定性错误的定义身上，直接修改 $t$ 步的决策，由此看后续的任务是否可以完成，如果完成，则证明该步时决定性错误。
2. 对于一个长 Session 里面的多个 React 循环，可能多个 trail 都是错误的（因为 LLM 可能先去试错），Dover 针对于每个 trail 都单独划分，然后从每个 trail 里面去找错误点，这样在缩短上下文的同时还可以针对失败任务进行不同路径的修复。

3. 主管（Orchestrator）和子智能体（Sub-agents）之间的责任往往纠缠不清，DoVer 在做干预时，明确划分了两个层次的修复手段：
   1. 直接修改主管的计划或者发给子智能体的 Prompt。
   2. 子智能体无法完成，可能是因为工具缺失，通过创建新工具来辅助任务完成，这一步是直接修改 Harness 框架了（可以联接到 RSI 这一方面）

Dover 分为四步：

1. 试验切分：以智能体系统自我反思后的“重新规划步”为切分点（图 2 中的蓝色方块），把一条冗长的完整失败轨迹 $\tau$ 切分成若干个独立的 Trials。这样做可以缩短上下文、支持并行干预、多路径修复。
2. 故障归因：针对一个试验轮次 $\tau^i$，使用 LLM + Prompt 生成候选故障归因假设 $h_i$，且 $h_i = (\hat{a}_{\hat{t}}^i, r_{\hat{t}}^i)$，其中 $\hat{a}^i$ 是嫌疑智能体，$r_{\hat{t}}^i$ 是自然语言写成的错误分析。
3. 干预生成：将 $h_i$ 转化为 $\hat{t}$ 步上下文的具体、最小化的文本编辑操作 $I_i$，其中操作分为上面提到的两类。
4. 干预执行：将系统状态回滚恢复到第 $\hat{t}$ 步之前的快照 $\sigma_{\hat{t}}$，用干预生成的新消息 $I_i$  替换掉原本的错误消息 $m_{\hat{t}}$，然后继续执行。

## 指标

1. 施加干预并重跑后，最终成功解决任务的试验运行占比，但对于没有成功解决的，也需要衡量决策是否让任务执行更正确了。论文通过：对于带有人工标注解题步骤的数据集（如 GAIA），先用 LLM 从人类标准解题过程中提取出最多 $K \le 5$ 个与具体工具无关的关键里程碑 $\{\mathbf{m}^1, \mathbf{m}^2, \dots, \mathbf{m}^K\}$，对于任意一条执行轨迹 $\gamma$，用 LLM 裁判比对它完成了几个里程碑：

<div style="max-width:100%;overflow-x:auto">

$$
A(\gamma) = \sum_{k=1}^K \mathbb{I}\left[\text{轨迹 }\gamma\text{ 达成了里程碑 }\mathbf{m}^k\right]
$$

</div>
比较干预后的新轨迹 $\tilde{\tau}_I$ 与干预前的原失败轨迹 $\tau$：

<div style="max-width:100%;overflow-x:auto">

$$
\text{Prog}(\tau \to \tilde{\tau}_I) = \frac{A(\tilde{\tau}_I) - A(\tau)}{K} \in [-1, 1]
$$

</div>

2. 论文为了保持 LLM 是否真的按照 $I_i$ 走下去，还设置了 LLM-as-Judge 来判断是否一直符合修正后的要求，并划分了四个验证状态。

**表 1. 干预后故障假设的验证结果类别。**

<div class="survey-table" tabindex="0" role="region" aria-label="表 1. 干预后故障假设的验证结果类别。">

| 验证结果类别               | 判定条件（基于 3 次独立重跑）                                                     |
| -------------------- | -------------------------------------------------------------------- |
| **1. 验证通过**    | 3 次重跑中，**至少有 2 次完全成功**解决任务。                                          |
| **2. 部分验证**    | 成功次数 $\lt 2$ 次，但**至少有 2 次**同时满足：  <br>① 忠实执行了干预<br>② 里程碑进展度 $\ge +20\%$ |
| **3. 驳回 / 证伪** | 成功次数 $\lt 2$ 次，且**至少有 2 次**同时满足：  <br>① 忠实执行了干预<br>② 里程碑进展度 $\le +20\%$ |
| **4. 未决**      | 不满足以上三种的所有其他情况                                                       |

</div>

## 自我改进
这是作者期待的两个未来方向。在论文中，作者通过人机协同，优化并添加了一些工具，使得智能体在高难任务的表现得到有效提升，但我认为应期待：(i) 完全自动化的调试闭环（即 RSI），其中 DoVer 的洞察反馈给自动化的子智能体改进（例如利用代码智能体来实现修复）；(ii) 具备能力感知的干预生成，当不允许修改代码时，允许 DoVer 根据已知的子智能体能力边界量身定制干预措施。这两个方向均有助于实现构建鲁棒、自我完善的多智能体系统的目标。
